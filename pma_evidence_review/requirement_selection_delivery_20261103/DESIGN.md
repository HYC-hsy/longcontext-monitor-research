# Optional full-bank P2 navigation and evidence reader

Candidate `requirement-selection-view-v1`, local branch `pma/requirement-selection-view-v1`. Not pushed. It builds on the tree of remote P1 delivery `f656c6099f55db467987054e89bede4d4664c137` (local equivalent `2d1f1b2802b4edf703f4ba0a2751de723b8784aa`). This is a new explicit P2-only API, not an automatic Task integration or a change to the published P1/default P2 behavior.

## One frozen version and stable identifiers

`RequirementSelectionView(p1)` freezes the entire committed active bank, original task, task ID, fixed requirements, body/category, source refs and accepted event table, between serial P1 maintenance calls. It rejects uninitialized requirements or a bank inconsistent with the committed bundle. Internal memory IDs remain intact. Full-snapshot P2 aliases M1…Mn are assigned once in source acceptance-range order, using the existing requirement-state ordering; unknown source order stays explicit. They never reuse the P1 subset's numbering.

The existing real BM25/display-capture code determines the initial subset. Its IDs are mapped into the full P2 aliases; hidden items are not renumbered into the displayed prefix. Initial prompt/report explicitly distinguish all-active coverage from a subset. Every body is shown once with category, requirement attributes and source-association metadata. Initial group lists reference those aliases. TASK remains the entire original text; STATUS is one internal progress item and is not selectable. Requirement classification is neither evidence nor a completion state.

The fixed full snapshot is the source for every browse, source read and final selection. Live P1 changes cannot silently replace its body or sources. Before returning an intervention, active body/category/ref and task identity are revalidated against that snapshot, then the unmodified `tag_selection_contract.dispatch` and `delivery_json` return the selected original strings. Caller-visible `pending_refs_valid()` repeats the live check for delayed delivery and marks revocation. A host must retain its normal serial lock through final validation/enqueue, or revalidate before enqueueing; this prototype sends nothing to an Actor and does not claim atomic integration with Task delivery.

## Optional tools and full-bank visibility

`memory_browse(view?, requirement?, cursor?)` has flat `all` (default), `requirement` and `unclassified` modes. Requirement mode accepts a supplied fixed sentence (same conservative NFC/newline/outer-trim normalization); unknown names explicitly fail and never create groups. Filters query **all frozen active records**, not just the initial BM25 subset. Multi-requirement entries retain one alias/body and can appear under multiple filters. Per-filter entries are deduplicated by original ID, never by content or apparent execution similarity. Unclassified records remain reachable. Shared themes do not add sources.

Record JSON is paged through the existing 8000-Unicode-character whole-JSON pager, with start/end/total and signed next_cursor. A long record may be split across pages; concatenate its record parts and JSON-decode. Cursor authentication binds the snapshot, filter and fields. Only completely returned record ranges, or complete initial records, grant final M selection. Partial or guessed hidden aliases are rejected. Full-snapshot scope does not promise all matching bodies fit in one page or the finite model budget; matching/all-active counts and partial transport status remain explicit.

`memory_read_source(memory_id, view?, cursor?)` is an optional evidence tool. Use the **same stable P2 M alias** from the initial view or returned record.alias, TASK, STATUS, or a returned P2H handle. Raw memory IDs, P1 M numbers, raw P1 H1 handles and arbitrary event/path/archive IDs are not additional entry points. Sources mode reads only selected/inherited originals; default auto uses context only when no sources are linked. Explicit context reads the entry's bound generation window, not the current prompt. Missing/corrupt context is reported; intact selected sources remain independently readable. Partial transport is never semantic completion or proof. A+B selecting only B still has only B as its selected source; its input-history directory can independently lead to frozen A and A's original receipt.

## Physically read-only P2 and session authority

The P2 adapter reuses SourceLinks.read and RequirementHistory, with an isolated SnapshotLinks state and **in-memory-only commit** for grants. It copies only root/path data, not P1 instance methods or writer instrumentation. It never calls the P1 state writer, captures windows, writes a journal or changes memory contents. No P2 grant competes with P1 persistence. This refers to memory/source storage; a separately supplied real client may still produce its own transport logs under its existing policy. Frozen legacy P1 grants are retained internally only to validate already-bound historical citations; they are not exposed as public read authority.

Returned directory handles are wrapped as `P2H.<selection nonce>.<original H1 capability>`. Only whole directory entries actually returned grant their wrapper in this session's in-memory registry. The public endpoint rejects raw P1 handles, foreign-session wrappers, fabricated/unissued wrappers, hidden active entries and arbitrary files. Independent per-snapshot cursor keys prevent replay across sessions; existing task/window/record hashes and archive path checks still apply. H reads remain historical and cannot be selected for Actor delivery. Deleting live old memory preserves the frozen historical chain; changing/deleting a selected live record revokes final original-text delivery.

Signing keys remain private internal data. Never log/dump `view.links.state` or the P1 bundle: the shallow adapter object still carries the P1 source secret for validating old capabilities. The API returns only public handle/cursor strings, visible receipts and selected original text. All grants disappear with the P2 object/session; there is no durable P2 resume or cross-session capability transfer. A crash requires a new selection snapshot/call, rather than pretending prior reads happened.

## Calls, failures and delivery protocol

`RequirementSelectionAgent(p1=p1, llm=existing_client).select(...)` is explicit and opt-in. It does not call P1 maintenance. With zero tools, it makes one P2 logical call and can directly return `<intervene>TASK,M…</intervene>` or `<no_intervention/>`. Browse and source reads share a four-call limit. There are at most two continuations/three logical P2 calls; only r0/r1 have tools and r2 has none. Budget-exhausted receipts preserve earlier completed reads. The extra tool/schema/prompt tokens and any requested continuation calls are real overhead; physical provider retries are inherited/unknown. P1 initialization and maintenance budgets remain separate and unchanged.

Raw parsed calls and visible results, actual attempted/completed logical calls, usage exposed by the client and actual prompt/system/schema hashes are retained in the in-memory report. Unknown/write tools and invalid arguments stop later batch operations. Missing sources/partial pages are explicit receipts, not automatic semantic failure. Transport failure, invalid final output, unshown/partial selection or stale selected bindings return errors with no delivery; they are never substituted with no_intervention. No mandatory evidence read, new evaluator, reviewer, correction policy, model or completion checklist is added.

`process()` remains blocked for the P1-only class. The new P2-only class also blocks process(), requiring select(); neither starts a Task or exposes memory-write tools. The existing final XML parser/alias dispatch and original-text JSON delivery are reused, with no rewritten advice, grouping metadata or evidence fragments passed to the Actor.

Regressions cover actual top-20 BM25 versus 59 full records; flat and requirement browse→evidence→exact original selection; unclassified/multiple requirements; lossless long UTF/CRLF/escaped paging; partial-record denial; selected/context/H source differences; deleted history, unissued/session handles, missing context, independent sources; late delivery revocation, budget closure and invalid/write tool denial. Whole P1 archive byte comparisons remain identical during P2 operations. The old published P1's 104-file verifier still passes, and old default P2 tests are included.

No real model/profile, Task, native evaluator or public push ran. Fake checks establish engineering behavior, not semantic improvement. A large group, long record or distant ancestor can exceed two serial readable turns; explicit partial status/cursors do not grant unread selection. Full-source files remain at their original immutable archive paths and are rechecked, not duplicated into another evidence database; missing/corrupt files stay unavailable. No durable P2 restart, multi-process archive locking or live Task/Actor enqueue adapter is claimed.
