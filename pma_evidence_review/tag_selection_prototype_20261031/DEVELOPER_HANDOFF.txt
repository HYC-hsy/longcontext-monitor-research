3. 程序负责的边界
任务信息由宿主提供，模型不得更改。候选只取审核成功提交后的正式版本，不取草稿、返工输入或拒绝项。候选预筛选和上下文预算沿用现状，不新增任意数量/字符上限。
程序保存调用与快照的对应关系，回调必须使用发起该调用时捕获的快照，不能拿最新一轮 M1 对应表解释上一轮返回。多次调用可复用别名，但不得复用响应绑定。
仅接受完整匹配的一个合法决定；未知/重复标识、空干预、额外正文、属性、嵌套标签、多重/冲突标签和旧 JSON 都明确报错。
允许模型输出前后空白，以及规范化一层完整的外围 Markdown 围栏（无语言标记、xml 或 text）。围栏外不得有其他文字，不从混合文本搜索一个看似合法的片段，不递归剥围栏。保留原始返回、规范化结果和是否规范化的标记。
发送前检查调用周期和任务版本仍有效；所有被选条目的当前 revision 和内容身份必须与快照一致。变更、删除或失效则整次选择报错，不替换为新正文、不发送一部分。这采用生产适配器的撤销策略，取代旧 JSON 原型“周期内继续发送旧内容”的策略；测试与文档必须一致。
校验和发送须处于一致的宿主时序，复用现有串行调用/锁，不另造通用并发框架。程序按冻结原文装配，保留 Unicode、换行和条件限定；转义只用于可靠传输，解码后的正文不改变。
只读选择不得增删记忆或关闭 gap。格式错误、过期选择、传输错误不得计为模型主动 no_intervention，也不得改走自由生成提醒。检查 vendor process 把 None 统一算 NO-OP 的路径，保留独立结果和统计。delivery_json 只生成成功干预的所选原文块，错误和不干预均不产生提醒；diagnostic_json 的原始响应、规范化标记和错误仅存宿主日志，绝不能拼进任务请求。
