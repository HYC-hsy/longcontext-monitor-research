## Original behavior reused and actual output connected

Pinned PMA `yifannnwu/proactive-memory-agent@89e5c0d6aadfe531a1aee42fd290d48be89973dd`, Apache-2.0, defines PHASE2_SYSTEM in vendor/pma_89e5c0d/src/memory_agent/memory/memory_agent.py. It explicitly asks for synthesized context_for_action notes, connection of memory and current behavior, and calibrated no_intervention. The new SYSTEM retains that entire constant as its prefix and appends one protocol/grounding paragraph. It describes memory as a fallible overview; evidence inspection is optional, not a per-entry or per-topic audit. Original useful intervention/non-intervention conditions remain intact.

`RequirementReminderAgent.remind()` is the new P2 target. It shares the frozen bank, read-only tools and bounded optional loop with the isolated `RequirementSelectionAgent`; its actual renderer, system, final-turn instruction, parser and delivery are different. There are no TASK/M-only output instructions in the generated path. It accepts a whole `<context_for_action>note</context_for_action>` or `<no_intervention/>`, then calls the actual pinned `MemoryAgent._parse_phase2_response`. Output is the synthesized plain note body in context_for_action/delivery and should_inject; it is not alias-expanded JSON or a concatenation of original memory. Original parser trimming is retained. With no native tool calls, a complete final reminder/no-op is recognized before any legacy tool-text scan; literal tool XML inside that reminder remains note data. Native tool calls are not inferred from visible examples. Native calls mixed with final control markup, or outside-final text tools mixed with final tags, fail explicitly with zero tool execution. Tool-only legacy text fallback remains supported. Whole-response framing is stricter than upstream because upstream silently treats missing tags as no-op: malformed, mixed, empty-note or old alias-selection output is an explicit protocol error, not fabricated non-intervention.

`RequirementReminderPipeline.run(entries, observation=..., step_count=..., cycle_id=...)` explicitly composes the existing P1 maintain() and this generated P2 using the **same existing p1.llm client**. It neither calls the prohibited P1 process() nor relies on VerbatimSelectionMixin to parse notes. If P1 returns incomplete/failure, P2 is not called. P2 failure/revoked delivery remains an error. Raised P1 persistence/journal exceptions can bypass returned counters; those counters are explicitly unknown rather than guessed from a stale report. Both independent process() guards remain. This is a callable prototype, not a Task/Actor enqueue integration.

No complete upstream process() was copied: that path swallows some phase errors/defaults malformed output to no-op and records hidden reasoning fields. Existing persisted P1 behavior and explicit error reporting must remain. Direct reuse includes original PHASE2_SYSTEM/parser, PMA bank/BM25, display capture, SourceLinks pager and frozen history; new code is the small adapter/explicit composition. No second model, evaluator, semantic verifier or graph/embedding store was added. Existing vendor LICENSE stays intact.

## One frozen bank and optional views

Every invocation freezes the complete committed active bank, task, requirement attributes, body/category, source refs and accepted event table. Stable P2 M aliases are assigned once for the full snapshot; initial BM25 IDs are mapped into them. Initial scope explicitly says all-active or subset. The original task is supplied in full, not reconstructed from requirements. Original IDs remain in host audit metadata; model-facing rows show the stable current M label only. Multi-requirement membership and unclassified records stay reachable; classification does not support a claim or establish completion.

`memory_browse` supports flat all, fixed-requirement and unclassified views over **all frozen active entries**, with optional knowledge/procedural/gap category filtering. Counts and matching category counts are counts of stored active records. GAP records describe recorded unresolved conditions/answer needs; zero GAP records is not proof of task completion, and a GAP's existence is not proof of failure. No dynamic requirement creation or mandatory full-topic sweep occurs. The tool uses the existing 8000-character whole-JSON pager. Full/partial status and next_cursor refer to transport only.

`memory_read_source` optionally follows the same fully shown P2 M alias, TASK, STATUS or an actually returned session P2H handle. Selected sources, frozen generation context and input-history directories remain distinct. Default auto reads selected sources and only falls back to context when no sources are linked. Missing/corrupt originals are reported; intact selected sources remain readable independently of broken context. A+B selecting B does not acquire A as selected evidence; A can separately remain reachable through its frozen history handle. Arbitrary memory/event/path IDs and raw P1 H handles do not create access rights.

P2 grants live only in SnapshotLinks memory, with new session prefixes and cursor keys. No P1 writer or its instance instrumentation is copied; sources/bank/grant files are not written. H grants are issued only for complete returned directory entries. P1 origin signatures remain internal to validate old bound citations, never exposed as keys. Returned handles are not keys and do not transfer across sessions. Caller/client transport logging is separate from this storage guarantee. Never dump snapshot links state or the P1 bundle.

The new note is free-form: the host cannot infer a used-record subset, per-claim support, or factual quality. It revalidates the **whole frozen bank, refs, fixed requirement catalog and task**, rather than inventing source attribution. pending_refs_valid() repeats this before delayed delivery. The verbatim compatibility class still checks its selected subset and uses the original XML/dispatch unchanged. A real host must hold its serial delivery lock through validation/enqueue; no Actor message is sent by this prototype.

## Settled P1 boundary and interruption repair

Both snapshot construction and delayed validation read the actual persisted P1 bundle, verify its checksum, and require agreement with the cached links state and the actual live p1.memory.to_dict(). Direct uncommitted body, STATUS, GAP or entry changes revoke both fresh and delayed output, even when the stored bank itself still matches the snapshot. Active flags alone are insufficient. Pending, initializing, running, unknown or malformed cycle phases reject P2, even if process activity flags were cleared by a crash. done and explicitly host-acknowledged abandoned retain the existing P1 terminal-phase semantics; this is not a semantic assessment of memory quality or an automatic rollback.

The exact regression saves a replacement and interrupts before deleting the old entry. Both remain in the committed bank, active flags clear, and the durable cycle remains running. Fresh P2 makes zero model calls, reopening still refuses the bank, and a previously prepared delivery is revoked. The check also rejects unreconciled/corrupt storage and applies to no-intervention decisions; it does not turn failures into silence. Existing P1 save/update/delete/recovery policy was not modified.

## Budgets, evidence and limits

P2 can directly write a reminder or no_intervention in one logical call, with no tools. Optional browse/evidence reads share four calls and two continuations (three P2 calls maximum); the final turn has no tools. Tool/schema/prompt tokens and continuation calls are overhead, not free. The pipeline separately counts P1 initialization/maintenance: a simple fresh init + one maintenance + no-tool P2 is three calls; maxima are seven on a fresh initialized cycle and six later. Client/provider retries are inherited/unknown. No new profile/client is constructed.

Strict fake-only result: **181 passed, zero failures/errors/skips**, including generated note/no-op, both browse→evidence→synthesized-note paths, missing evidence, recorded GAP counts/filtering, original prompt consistency, independent combined entry, P1 failure short-circuit, whole-bank version revocation, durable interruption and compression checks. Existing source, history, alias and default-P2 regressions remain included. Offline regressions are not reruns of old real experiment groups. All real model, Task and native evaluation counts are zero.

Real semantic benefit and model compliance are untested. The host does not prove synthesized claims or that uncertainty language was adequate. Large groups/records/history may exceed the finite read budget; pages remain partial. P2 has no durable resume or multi-process locking, and sources must remain at the existing immutable archive paths. Task integration and actual enqueue remain future work; upstream no-op fallback is intentionally not replicated. The current follow-up passed independent review and was published after user authorization; no real run occurred. No raw private runtime directory belongs in the delivery.
