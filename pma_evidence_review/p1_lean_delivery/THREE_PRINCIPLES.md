# 完整性、简洁性、自然性复检

本记录是对实际 system 与工具接口的静态审读，不是模型语义效果实验。

## 完整性

- PMA 原版首轮四项、后续四项整理角度逐字保留；事实、经历、GAP、内部状态和删除五工具不变。
- 保留任务要求优先、重要工具结果、失败与修复、范围/时间/版本条件、观察与推断、计划与执行、未知与失败的区分。
- GAP 与其他内容平级，依据任务要求或观察；部分进展保留未满足部分，不能随眼前阻塞一起关闭全部条件。
- 明确保留仍有用的早期失败，避免成功后只剩最新结果。
- 可见检查的覆盖、断言、预期与任务不符仍可整理成 GAP；检查有缺陷不等于实现有缺陷。

## 简洁性

- 合并重复的维护、经历、状态和范围要求，没有新增类别或额外输出报告。
- 删除绑定枚举、匹配分数、发布原子性等内部实现解释；相应实现和输入中的来源标签保持不变。
- 编号更新只保留保存工具所需用法；证据可选，保留引文数组和 XML 必要编码说明。
- 工具完整 schema 和描述没有增长，不是把 system 的文字搬到别处。

## 自然性与歧义修正

初稿“更新条目使用编号”可能误含状态更新。复检后限定为 save 工具；状态工具没有 memory_id，按现有 schema 更新。

初稿“重复日志不算新尝试”可能误伤独立执行产生相同输出。复检后明确：重读同一事件不算另一次尝试，但不同实际执行仍分别计数；没有返回结果则结果未知。

“不再需要即可删除”过宽，改为退役过时、错误或重复条目；同时明确有用失败仍保留。

GAP 增加“依据任务要求或观察”，这里是 OR，不要求初始化时任务与执行证据同时存在；未验证要求不能改写成已观察到失败。

## 结论与边界

复检没有坚持最初 2662 字符的长度，补回必要语义后为 2823 字符。原版八项内容角度保留，但文字精简不等于模型一定遵守。工程测试验证实际提示接线、接口与送达，不验证模型能正确整理或选择。
