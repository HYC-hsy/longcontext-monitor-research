# 补齐来源存储、关联与读取：设计稿

2026-11-02。基于P1候选c5678323和MAGE/SAM固定实现的只读核查。尚未实现、未运行真实模型或Task。

## 一、范围

继续MAGE启发的“P1写摘要、摘要可回查”路线，不改成DMS式只选原文。P1仍维护事实、经历、GAP、当前状态；P2未来把摘要作为索引、按需读原始记录再形成简短提醒。此次先补三项底层缺口，不引入树、执行回退、审核者、效用评分、模型编写证据报告或任务规划器。

## 二、统一数据流

宿主收到真实可见动作/回执 → 一次写入事件表并分配稳定ID → P1输入展示短号 → P1写摘要并选择来源短号 → 工程冻结条目与来源引用 → P1/P2用同一个只读工具按需读取原文/续页。

### 1. 事件集中保存

- 事件表按当前task/run隔离，仅采集允许进入模型的可见字段；不导入隐藏thinking/signature、凭据或私有profile。
- 每个真实接受事件保存一次，保留动作参数、对应回执、可见Actor自述、宿主已知的顺序及调用ID。自述与工具结果明确分开。
- 命令/回执配对使用真实调用ID；未知或歧义关联标明未知，不按文字相似推断。
- 窗口只引用事件ID，保留new/previously_presented等标记。每次实际模型输入及请求哈希仍作为独立审计快照，不为去重牺牲可追溯性。
- 同输出的不同调用不是同事件；删除记忆不删除原始事件。
- 不替模型猜“独立环境”“已持久化”等语义；工程只记录宿主真正知道的上下文。

### 2. 摘要来源关联

保持现有三种save工具及update_status，只增加一个source_ids列表参数。content仍是P1写的简短摘要。来源短号来自当次输入，不要求模型复制引用、计算哈希、写行号或逐句证明。

- E类短号：本次展示的实际事件。
- M类短号：本次展示的旧记忆；模型沿用旧记忆时可以引用它。
- T类短号：原任务原文段落，或完整TASK。
- 宿主按本次请求的冻结映射立即解析为稳定内部ID，避免跨轮M编号变化绑定错条目。

必须承认：**哪些材料与这条摘要有关，是模型的语义选择，工程不能自动完成。** MAGE的Store只有一段pending材料，而PMA一轮可写多条不同内容，不能把整窗自动当成每条摘要的精确来源。

工程处理：
1. 校验来源ID属于当前任务和实际已提供的内容，拒绝不存在、跨任务、未来来源；失败时不留下半条绑定。
2. 对事件引用补齐真实调用的命令/回执关联，保留先后顺序。关联单位是完整事件，不只保存某一句成功输出。
3. 对旧记忆引用冻结其当时来源集合，继承底层事件ID，并标记“经旧摘要继承，模型未必读过原文”。不把继承当亲自核验，不需要可编辑版本图或树。
4. 原任务引用保持要求身份，不把要求当完成证据。
5. source_ids空缺或空列表时，条目可保留但明确标为“未指定条目来源”；原生成窗口仍可作为宽范围上下文回查，不能自动补成精确来源。旧无绑定条目同理。
6. 当前status也保存相同来源绑定，随状态更新原子替换；状态仍是派生文本，不是工具事实。旧审计快照照常留存，但不做新的状态版本管理界面。

“来源集合”代表模型选用/继承的材料，不代表这些材料证明所有句子。模型仍可能漏选或选错，不能以工程校验通过宣称语义准确。

示例（示意，不是新增测试案例）：
- P1摘要：“当前脚本设置PATH后sqlite3可运行；后续独立调用尚未确认。”
- source_ids选择相关E短号和任务T短号。
- 程序解析短号、保存真实事件、关联调用结果；不补写“已经持久生效”。

### 3. 可续读原文，而非整条省略

保留一个只读工具，逻辑接口为 memory_read_source(id, cursor=None)。id可定位记忆/当前状态的来源包，或已展示的原始事件；具体旧参数名兼容由接入时处理，不能增加多个作用相同的工具。

- 初次读取给出所选来源的事件目录、来源角色和预算内原文；不再重复返回“完整model_input＋同一批events＋完整source_text”多份相同材料。
- 可继续沿用8000字符作为初始页预算，但预算含返回包装；关键变化是超限续页，不是把事件整条丢掉。最终预算须在接入前根据实际渲染开销冻结。
- 长回执按原字符串连续区间拆分，分段保留事件ID、调用ID、字段、原文范围及part信息。拼接恢复原始允许可见字段；不使用split/join改变空白，不让另一个LLM重新摘要。
- next_cursor由工程生成并绑定task、来源包快照和读取位置，模型只原样传回；不暴露任意文件路径读取，不接受模型编造偏移来访问其他任务。
- 每页明确是否还有未读内容；预算耗尽、缺失、未关联、部分返回与完整返回是不同状态。没有读完不能标“证据已完整核对”。
- 读取循环须允许在预算内再次传cursor；不能仍在首次读取后永久关闭工具。总模型/工具预算与实验范围必须在实现验收时显式固定，不默认无限循环，也不保证单轮能读完整段历史。
- 完整性指“所有保存的允许可见内容可寻址”，不是强制每次全读。首轮仍以当前相关条目为入口，避免全库扫描。
- P2仍需要近期真实动作/回执：条目生成时的来源包不包含未来反证，本设计不宣称自动检索到所有后续变化。

## 三、具体借鉴哪些代码，哪些不搬

|来源|可借鉴内容|不照搬部分|
|---|---|---|
|MAGE ExplorationTree / Store|原始事件集中存储、摘要保存covers_node_ids、上下层分离|树分支/回退；按action.name＋observation合并但忽略参数；没有现成read_source，不冒称直接移植|
|SAM cabeza PageStore|工程分配页号；摘要目录与raw_content分离；render和原页存储分工|原始内容strip和默认补文；内存列表不代替已有持久化身份/哈希；SharedPageStore真实淘汰旧页不用于证据库|
|SAM page_memory分块|尽量保持动作/结果组，超长单消息分为cont续段而不是整条丢掉|其组装不等于真实call_id校验；非tokenizer分支split/join改变空白；serializer包含reasoning字段，不复制|
|SAM MemoryTool|从摘要目录选相关页再读取的使用方式|execute调用consult_pages，逐页再调用LLM提炼，最终返回新摘要；不用于我们的原文回查|

## 四、模型新增负担与工程职责

|模型负责|工程负责|
|---|---|
|继续写短摘要；多选几个当次可见来源编号|编号、存储、冻结映射、配对、顺序、引用继承、哈希、分页、游标、截断状态|
|根据需要决定回查哪个条目/是否续读|确保返回来自指定来源，不静默遗漏、不重写原文|
|P2未来决定是否提醒并写简短说明|附实际用到的来源、记录读到哪些部分和最终送达内容|

不要求P1解释“为什么这些证据足够”，不新增审核流程。来源选择仍会出错；换成全部自动关联虽省一点模型选择，却会回到整窗索引问题。这里选择增加一个短ID列表，换取更明确的条目级范围。

## 五、工程验收边界（本轮未执行）

先离线验证：同事件不重复存；同文不同调用不误并；命令回执不串；缺失引用不伪造；旧摘要继承不冒称直读；删记忆后原事件保留；长事件分页拼接逐字一致；游标跨任务拒绝；status与source_ids同步；无关联来源如实返回；真实输入快照不丢。

通过工程验收仍不等于P1少推断、P2更有效；语义效果待用户恢复验证条件后单独检查，不重跑旧组。本稿不启动新案例、真实模型、完整Task或原生评价。
