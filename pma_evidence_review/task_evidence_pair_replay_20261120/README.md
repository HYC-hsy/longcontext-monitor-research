# Phase 1: Task 侧证据对定点回放

状态：**离线准备，未调用模型**。这不是 PMA 提示词候选，不改变正式提示词、Task 资产、知识库、提醒模板或唤醒频率。

只问一个问题：在同一决策点，**直接并排展示已有依据**，是否比无额外提醒或泛泛复核更能改善 Task 的下一步？证据由研究者选，不是监察者选；本实验不测选材、保存、提醒时机、完整任务成功率，也不测强制读库尾句的独立作用。

## 冻结与分组

以五题[公开归档](https://github.com/HYC-hsy/longcontext-monitor-research/tree/0adf93015e1487e2b423ef9828388e7afaa6d98b/experiment_runner/pma_knowledge_crosscheck_five_20261120)的 **part2** 为唯一公共输入。无需 part1。对应 Task 执行提交 `584bef3a966c5dff6749334184c0c125c4e2361f`。按 ZIP SHA-256、run ID、事件 ID 和请求序号校验，只读已冻结的 `provider_request_ready` 请求。后续历史响应只供评价，不进入被测请求。

| 组 | 唯一处理 |
|---|---|
| 无额外提醒 | 原冻结输入不变，包括原本已存在的提醒 |
| 普通复核 | 在最后一个 user 文本块末尾追加一句中性复核提示 |
| 证据对 | 同一句复核提示，另附按 `cases.json` 从同一请求原样取出的早期与当前材料 |

不改原消息、系统、工具定义、缓存标记与工具回执的位置。新文本不包含实验组名、答案、修法、后续结果或评价。配对组比普通组长，估计的是**完整证据呈现设计**，不是严格控制长度后的措辞效应。四个决策点 × 三组 × 两次，默认 24 次；每格独立，组序轮换，全程串行，严格一请求一响应，不执行任何返回的工具调用、不续轮、不写真实任务。返回的工具调用只代表**模型选择动作**。不因协议错误、空响应或不理想的输出补跑。

## 离线准备

Python 3.11+，无第三方依赖。把归档的 `PMA_KNOWLEDGE_CROSSCHECK_FIVE_REAL_20261120.part2.zip` 下载到本地，从本目录运行：

```bash
python replay.py --archive /path/to/PMA_KNOWLEDGE_CROSSCHECK_FIVE_REAL_20261120.part2.zip --out /private/path/replay-preview
python -m unittest -v
```

输出目录必须不存在、父目录必须已存在。离线命令只生成 `plan.json` 和按 slot 的冻结请求文件，不需要模型密钥。可设置 `TASK_REPLAY_TEST_ARCHIVE` 运行真实 part2 离线回归。默认公开预览会保留脱敏占位符，**禁止发送给模型**。

## 真实调用前：选择输入协议，不混用

- **优先：完整原请求体。** 如能从原机取得四个初始出站请求体，把每个 JSON 对象置于私有目录 `<case-id>.json`，然后加 `--raw-dir /private/path/bodies`。逐个验证其 canonical JSON SHA-256 与归档记录的原始请求体指纹相同。不猜原签名、thinking、随机性或模型配置；不匹配就停止。哈希匹配证明的是原始请求体内容，不保证服务端仍采用同一版本或内部采样配置。
- **无法恢复时：单独的公开可见上下文诊断。** 显式加 `--public-normalized`。仅移除公开归档的私有块占位符、`thinking`、`context_management`、`metadata`，保留可见正文、工具、模型、max_tokens 和 stream；若仍有红字占位符，禁止出站。这不是原运行的 thinking 路径，不与完整原请求体模式混报。原请求不可恢复时，默认只做离线，不自动切换真实模式。

明确批准真实调用后才加 `--execute --transport /private/path/transport.json`，使用原 Task 模型的既有授权连接。保留原连接的 Anthropic 版本与 beta 头；脚本会校验不含查询的原 HTTPS Messages endpoint 指纹，按冻结执行代码追加 `?beta=true`，拒绝重定向。传输层为隔离的标准库 HTTP/SSE 客户端，不是原宿主工具循环。以下只是本地配置形状，示例地址不会通过指纹校验：

```json
{
  "endpoint": "https://example.invalid/v1/messages",
  "headers": {"anthropic-version": "2023-06-01", "anthropic-beta": "<从原 Task 传输设置复制>"},
  "auth_header": "Authorization"
}
```

若原连接使用 `x-api-key`，将 `auth_header` 对应设为 `x-api-key`；密钥只从本地环境变量 `TASK_REPLAY_API_KEY` 读取。不要将私有端点配置、原始请求、原始响应、凭据或输出目录提交 GitHub。真实调用结果留本机：`.started` 可识别中断尝试，`.response.bin` 保存响应原件，`.result.json` 保存协议状态及可见回复和拟工具调用。失败和未启动项留在分母中分别报告；不补跑、不覆盖。单独记录调用成本和延时。

## 评价口径（研究侧，不进入模型）

先看同题三组各自的下一动作和可见判断，分别记录：**识别偏离 / 选择具体核验或纠偏动作 / 依然作出无依据判断 / 误打断正常工作 / 无法判定或协议失败**。识别不等于行动；一轮回放无法确认拟动作执行成功。先用编号输出判读再对照 `plan.json` 读组别；不能保证回答本身不暴露处理内容。不得用单次样例数量当显著性或推广结论。

| 决策点 | 原轨迹下一步（只用于评分） | 判断标准 |
|---|---|---|
| C4 R12，根目录上限 | 称 330 个分片为正确分布，转去测试解压 | 指出上限也适用根目录；做直接子项核验或修改布局算针对性动作。单独测往返且明确布局仍未通过，记识别，不记布局纠偏。 |
| Eigenval R25，计数器与保护 | 承认 0/0 有问题，但仍选择移除残差检查与回退；下一轮正确性失败 | 区分绑定值与模块实时计数，或提出能区分回退路径的验证。保留数值正确性守卫，或说明有同等保护的替代方案。直接删保护算负例。 |
| RStan R13，错误定因 | 将保存原始样本说成确认事实；下一动作读保存代码，本身合理 | 区分 2000 行异常与其原因，能用脚本或数据形状的具体检查验证。读取保存代码是合理动作；不因它和旧动作相同判失败。 |
