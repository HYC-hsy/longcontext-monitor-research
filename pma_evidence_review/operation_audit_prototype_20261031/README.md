# 完整操作依据与缺口反馈：隔离原型

生产基线：`48babf4302563bbe6e8f0d47e8c617d041a392b1`。本目录不改变生产入口或默认策略。

## 改什么

旧实现已经有整体判定、子项合取和返工。本轮不是首次增加 overall。
这份候选把审核组织为固定的四步工作流程，并要求整体理由面对本次操作的条件与证据范围。
证据不足时用简短自然语言说明支持范围、缺失条件和可行证据；建议不是唯一测试或已确认事实。

输入剥离宿主身份字段，保留完整语义目标、已有拆分、共享证据原文及来源角色和顺序。
输出使用自然三态名称，支持子项无需重复理由；工程承担标签关联、校验和聚合。
完整性、简洁性、自然性落实在流程和协议中，不引入 Skill/Plugin 加载器或新的模型调用。

## 使用

- `audit.py`：独立接口原型，不是可以绕过生产 gate 的发布器。
- `test_audit.py`：定向假响应契约检查，不证明模型语义效果。
- `HANDOFF.md`：生产接入边界与映射。
- `REUSE.md`：固定上游来源及实际借鉴范围。
- `fixtures/`：已公开历史 PATH 请求与旧响应，以及新候选的请求投影。没有执行新模型调用。
- `VERIFICATION.md`：最终本地检查和历史输入投影核对。

从本目录运行：`python -B -m unittest -v`。

开发接入仍需复用已有引文资格校验、版本核对、原有返工预算和提交链；不改拆分器、第二阶段、状态或 GAP schema。
模型是否真正改善完整操作判断，需要候选真实重放检验。不能以离线测试通过声称解决了 SQLite 错误。

## 成本边界

同一数据集复用已有旧组结果，默认只跑新方法，不自动重跑旧组。确需重跑应先说明理由与额外成本并取得用户同意。
先进行候选审核的窄范围验证，完整 Task 不在本原型交付中运行。
