# Fresh root release-review replay — prepared, not executed

This is an offline diagnostic instrument, not an online Supervisor mechanism. It does not reuse B/J/I, Task Book, Task/Supervisor history, the completion claim, or native evaluator material as model input. No reviewer call is authorized by this commit.

The exact final pre-evaluator workspace is the SHA-verified retained tar from high-budget run `crs-rhr-rer-v0-fyne-bji-high-budget-r1`. `materialize.py` extracts only public repository files into a Git-outside fixture. It excludes `.git`, run-generated completion markdown, the `.monitor_original_task_*` copy, monitor/private paths, and evaluator/solution paths. `FIXTURE_MANIFEST.json` enumerates every included file and excluded file with reason. The original public task is a separate exact file at `task/original_task.txt`. Existing public source and tests, the tracked patch, and untracked implementation `.go` files are preserved. The tar, patch, and each added source are SHA-bound; no posthoc result is used to edit the fixture.

`simple_fresh` starts with empty provider history and the full public task. `spec_first_fresh` also starts empty but first sees only the task and may use `file_read` solely on that file; it commits a free-text `review_basis`. In the second phase, its final tools and workspace are identical to `simple_fresh`. The basis is marked model-authored, revisable, non-oracle, and non-evidence. Both conditions finish through the same `finish_review(outcome, conclusion)` schema. No online control tools are present. The 300-turn ceiling is shared across the two phases of the spec-first condition and never sent as a countdown.

Each condition gets a new provider client and independent disposable workspace. `file_read` is scoped to the task and that workspace. `code_run` uses a SHA-pinned sanitized Debian image containing only a Go toolchain copied from the task image; it runs with `--network none`, no extra host mounts, and bounded time/resources. Full command outputs are archived, and pre/post workspace trees and changes are recorded. An implementation mutation outside `.review_probe/` is a protocol violation, not a change transferred to the other condition. The original task image's hidden evaluator/solution filesystem is absent from this tool image.

Future output slots record model-visible `model_input`, exact pre-send provider request snapshots, model responses, tool calls/results, usage, transport attempts, provider history, committed basis, final decision, wall time, turn count, and workspace diff/hash. Native scoring is posthoc only. `launch.py --validate` is zero-model. `--run` requires a separately supplied, identity-bound authorization JSON; none is created or committed here. Even with authorization, each condition must be launched into a fresh output path.
