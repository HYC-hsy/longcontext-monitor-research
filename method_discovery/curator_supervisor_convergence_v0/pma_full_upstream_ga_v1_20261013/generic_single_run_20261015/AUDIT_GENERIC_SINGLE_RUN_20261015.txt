Fixed 12-task preparation (not official evaluations)
----------------------------------------------------
TASK_INVENTORY.json records the full public/evaluator Git member set, blob
ID, mode, byte size and SHA-256, official image tag, local RepoDigest, image
config ID, platform, native/overridden timeouts, resources, network and
report contract. The 12 declared images were fetched from their official
tags and inspected locally; no alternative image or Dockerfile edit was used.
All twelve disposable no-network image probes checked that initial images
do not expose /tests, /solution or the Docker socket. The checks did not run
official verifier assertions, prove all task tools useful, install missing
Task-solving dependencies, or certify real provider compatibility. Individual
raw image_check_*.txt and pull_*.txt files give commands/results. The first
constraints-scheduling pull output was observed in the terminal but not
captured as a pull_*.txt; its final local image/digest is in the inventory.
Windows PowerShell captured the original console files as UTF-16LE. Every
captured test/image/pull log also has a `.utf8.txt` reading copy; the original
file remains unchanged. The two encodings must not be called byte-identical.
Native agent timeouts: 1200s for constraints-scheduling and
financial-document-processor, 3600s for reshard-c4-data, 900s for the other
nine. Native verifier timeout: 1200s for those first two, 3600s for reshard,
1800s for query-optimize, 900s for the other eight. The research 14400s
agent envelope is not the official native budget; the V4 launcher derives
12/4/16 multipliers accordingly, without changing native verifier limits.

Failure attempts retained, not silently upgraded
-----------------------------------------------
Early long-path fixture attempts failed before Task requests. A5 failed
before Harbor with "fixed clean native Harbor source unavailable"; A6 failed
at Harbor import because the wrong bench-root lacked adapters. A4 reached
the synthetic verifier but its background service was absent there, so the
synthetic test exited 1 and reward was unavailable. A7/A8 verified that a
simple stdout success label was insufficient: the readiness call received
HTTP 501 from an unrelated listener on the first fixture port; evaluation
subsequently saw connection refused. The final fixture uses a dedicated port
and an actual readiness request. B2 initially had normal two-stage fake PMA
calls but no reminder: the fake update condition expected the old tool marker.
B3 preserved that marker alongside the service status, exercising original
PMA save/selection and the next Task request. All failed private roots were
left intact, not overwritten or treated as successful evidence. Raw private
roots are E:\pma-ga-sr-a4/a5/a6/a7/a8-20261015 and B2; they are not uploaded
because they contain unprojected Task/provider and host-private records.

Public projection, counts, limitations
--------------------------------------
The public fixture is selected/redacted from the private originals; it keeps
request and response structure, tool results, phase prompts and linking IDs,
but recursively replaces hidden thinking/redacted_thinking and signatures
with a marker, original length and hash. Provider endpoints are redacted.
Private originals remain outside the repository. The fake transport/Harbor
calls above were actual offline I/O. Real Task model, real PMA/provider API,
official benchmark evaluator, training and scoring-model calls in this work:
0. Actual inner real-provider attempts/cost are therefore not estimated.
The profile says max_retries=8 for PMA, but original worker semantics control
actual retries; the field alone is not an observed attempt count.
The historical six-task run and this V4 route reuse the same fixed GA/PMA
vendor and Harbor adapter, task/PMA profile SHA identities, shared native
verifier and archive components. V4 changes task selection/materialization,
authorization granularity and control-process stopping. Full request-byte
equivalence to the historical run is not claimed, nor is target-image
official evaluation of all 12 tasks. No new24-slot authorization exists.
