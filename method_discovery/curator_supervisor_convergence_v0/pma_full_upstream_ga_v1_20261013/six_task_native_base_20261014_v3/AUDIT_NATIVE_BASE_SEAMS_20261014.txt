Changes and reasons
1. live_launcher._stage_verifier now accepts the V2 official_source_git_commit identity and the old official_evaluator_commit field only when each present value equals the fixed 2fd12b88aafdd04a52c298e3940bcb189f9766d6. Both present but different is rejected. The new draft and run spec retain the fixed source identity. A real exporter regression stages fixed Git blobs and checks mismatches.
2. _worker_clearance now proves worker process exit independently of memory save. sidecar_stopped contains run, stopped, clean, PID/exit and a separate PMA finalization object. worker_exit has run/task identity; worker_stopped_without_task_end supplies local_save, stop reason and remote_execution (possibly unknown). Missing or failed save is never labeled task_end_saved. The host starts a bounded worker-end process when agent_end_pending appears: two seconds for natural task_end, stop request, then ten-second cancellation grace. The original PMA save/error/retry code remains unchanged. A residual Task writer still blocks verification.
3. On Harbor timeout, a cancelled host exec can leave agentmain.py inside the Task container. NativeSharedTrialHooks targets only that GA process with TERM and reads docker top again; any remaining new PID or GA writer blocks evaluation. writer_termination_check.json records before/after. Main container, writable layer and task mounts remain for Harbor collection/shared verification. In the first B timeout attempt this guard correctly blocked; the bounded stop was then added and tested.
4. The external GA adapter byte identity was 8a4513c6b28befe747d581d22e94cd2715f20234c63115e0ea424a56d033c3a0 and is not overwritten. It raised generic RuntimeError on a confirmed nonzero wrapper return. The research subclass now maps only that exact post-metadata failure, with matching run, archive_status=failed and nonzero wrapper_return_code, to Harbor's NonZeroAgentExitCodeError. Setup, identity, protocol and other RuntimeErrors are not reclassified. Actual Docker/Harbor nonzero path was exercised.
5. A fixture-only flag, requiring matching synthetic-only markers in both manifest and one-use authorization, allows the actual batch_controller -> live_launcher -> Harbor path to use the preexisting local fake gateway and --disable-verification. It cannot turn the unarmed V2R6 draft into a live authorization. The fake gateway captures actual send-boundary requests; no official benchmark test.sh is executed in this fixture.
6. FILE_HASHES.json in this amendment uses repository-relative paths; source_fixture/source_relative identify external disposable fixture origins without fixing an E: checkout. Source identity is the SHA-256 of each HEAD Git blob plus a clean-worktree check, not the platform-dependent read_bytes() hash. Earlier failed fixtures 01 and 07 are preserved under fixtures/ with their failure identity. The successful controller entry is under controller_entry. Early controller attempts 01/02 are separately retained under controller_early_failures (01 had no captured stderr); neither is represented as successful.
