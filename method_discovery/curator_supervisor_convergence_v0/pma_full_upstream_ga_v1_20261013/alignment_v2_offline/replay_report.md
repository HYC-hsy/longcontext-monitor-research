# Unchanged historical quote and source-hint replay

## Result

The new host-owned alignment adapter was run on 32 actual historical evidence references from the SQLite and HTML public development logs. Every quote and original source hint was passed unchanged. The new source catalog was generated by production `_project_tool_text`, registration, and rendering for every eligible public source in that reference's actual prompt. No expected child paths, replacement source handles, expected categories, or witnesses are used to select candidates.

- 26 `exact_unique` references.
- 4 `exact_multiple` references, with all 2 or 3 candidates retained.
- 2 `unbound` references, with no candidates.
- 8 offline regression tests passed. Zero model calls, real task runs, or hidden-evaluator reads.

These are binding outcomes, not verified facts or semantic support. This does not demonstrate improved model choices, decisions, completion, or online performance. The same historical model output strings can now be offered to the new quote/optional-hint alignment API without a developer selecting their decoded source. The surrounding historical memory operations, IDs, and whole transactions were not replayed.

## Important differences from the previous replay

The previous archived explicit-field replay returned 26 accepted, 3 ambiguous, and 3 not-visible references only after developer-authored child selection. Keeping the historical parent selection produced 32 not-visible results. That archive remains unchanged.

Here the original source handles are retained as optional hints, including the wrong-source hint, but do not filter or rank the search. New catalog handles are generated programmatically. Omitting the hint yields exactly the same returned refs for each of the 32 cases.

The apparent total of 26 unique matches hides two important changes:

1. `sqlite-C15-op1-ref1`, quote `Setting up make (4.3-4.1build2) ...`, old hint `s55685047fe45`: finds one exact quote in a different public source in the same actual prompt. The known witness is checked only afterward in the regression test, never used for catalog construction or matching.
2. `sqlite-C9-op4-ref1`, quote `./configure CFLAGS="--coverage -O0 -g" LDFLAGS="--coverage" --prefix=/app/sqlite/install`, old hint `sea5a52162558`: finds two tool-command sources rather than choosing the old selected child. Both candidates survive. A wider eligible catalog correctly exposes ambiguity the earlier single-source check could not show.

The three historical repeated compiler-command quotes each retain all three exact positions. The two noncontiguous quotations still have no candidate; combining separately present lines would fabricate a match and is not allowed.

## Exact quotes and provenance

`replay_report.json` includes all 32 complete unchanged quote strings, original hints, prompt and transport archive/line locations, quote hashes, binding status, and every candidate's typed role, source identity, generated handle, historical event handle, field path, position, visibility ref, and hashes. The replay asserts that extracting every returned ref reproduces the original quote exactly. LF, CRLF, quotation marks, and HTML/Python code are not normalized.

`real_public_fixture.json` from the previous archive remains the reference selection. The test regenerates it from the archived public gzip files and requires exact equality. The new runner verifies each prompt archive's recorded SHA and public line provenance before parsing it. It never reads hidden evaluation or adjacent-cycle sources.

## Source completeness boundary

This is a complete eligible **public-source header projection of the selected historical prompt**, not a reconstruction of the complete historical request/catalog:

- Each prompt contributes 5–37 public source headers, depending on the cycle. Production projection may generate multiple decoded child sources from each header.
- 6–9 `memory_derived` headers per prompt are deliberately omitted. The public snippets do not contain authentic historical revision identities; this replay does not invent them. Additional matches or ambiguity in these omitted derived memories are not measured.
- Only nonempty headers with the four supported public roles are eligible. The regression report lists omitted headers per reference.
- Header parsing is inherited from the fixed public-fixture extractor. It reconstructs rendered public snippets, not original event envelopes or every control/context section of the prompt.
- Registration therefore uses `record_digest_kind=public_prompt_extract`; it does not claim to restore historical accepted-event digests or source IDs.
- The decoded request projection is new. This is not a claim that the old rendered JSON wrappers themselves contained the quoted literal text.
- References were selected for earlier raw-source absence/non-uniqueness, include repeated citations across cycles, and are development data, not independent tasks or held-out evidence.

## Boundary regressions

Synthetic boundary fixtures are separate from the 32 historical references. They prove that an invalid or valid-but-wrong hint cannot hide a valid quote; repeated matches in one source and across observation/report/command roles all survive with their types; a hidden marker or quote spanning invisible text remains unbound; case changes, whitespace changes, punctuation changes, and noncontiguous text do not receive fuzzy promotion. These checks do not imply that any matched role establishes truth.

## Reproduce

From the candidate directory, with the pinned `regex` dependency installed:

```sh
PYTHONPATH=.:/tmp/pma_alignment_deps python -m unittest discover -s tests -p test_gap_evidence_alignment_replay.py -v
PYTHONPATH=.:/tmp/pma_alignment_deps python alignment_v2_offline/replay_historical.py
```

The temporary dependency path is the current audit environment's installation location, not a production path requirement. Code added for this replay is under 300 lines. Generated JSON is mechanical output, not hand-selected evidence. No historical file or old report was edited and no commit was made by this worker.
