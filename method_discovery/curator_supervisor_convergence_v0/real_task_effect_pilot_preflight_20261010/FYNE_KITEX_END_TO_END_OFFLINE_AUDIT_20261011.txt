3. Pilot entry, bridge and control lifecycle
--------------------------------------------
pilot_entry.prepare_run verifies fresh run root, exact task image, RepoDigest,
current source tree, profile-file hashes and arm membership. It stages a
fresh public task package, exact source bundle, Task-RW named volume, and
Harbor compose. T gets no Monitor route/worker/spool. S gets native
ASE+CRS-v0.2+RHR-v0+RER-v0+root_records_v1 and the fixed spool port. Both use
baseline_condition=original and condition_id=pilot-neutral. The true T/S
mapping remains host-side. Harbor whole-trial --max-retries 0 is in the actual
launcher argv, not merely the draft.

The trusted spool service runs concurrently with Harbor and adopts the
Monitor's own task_identity before opening its analysis port. Native Monitor
code_run uses the spool; the model can submit only fixed run-owned script and
session operations, never Docker flags, image, mount or host command. Host
PilotDockerToolPort pins the task image and named Task volume. Diagnostic
/app is RO; network=none; private HOME/TMP/cache/output and a scratch copy are
writable. Accepted requests, receipts and original scripts live under a
trusted host root outside model-writable scratch. Sources are rechecked for
redirected paths before each mount. UTF-8 script bytes are checked before
execution. Version-uncertain reads and private scratch diffs remain distinct
from actual Task product changes. No diagnostic patch syncs to Task /app.

At AGENT_START the hook checked the exact image, clean /app Git HEAD, RW Task
volume, network=none, RO source/runtime, S spool mount rights, and empty or
absent /tests. At AGENT_END it signalled the spool, waited for sidecar clean
receipt, stopped and restarted the same main container, inspected for active
Task/Monitor Python writers, and streamed the whole /app writable layer to
pre_evaluation_app.tar with SHA-256. It records legal_agent_end only if native
round_end_seen=true, wrapper_return_code=0 and archive_status=finished.
Verification is rejected if any legal/clean/frozen/product or evaluator asset
identity check fails. The fake verifier is a sentinel shell script, not a
native task checker; its output was never returned to the fake Task/Monitor.
The run-scoped cleanup only targets containers with this exact compose file.

intervened and the correction appeared in subsequent actual Task provider
