Read-only diagnostic connection actually tested
===============================================
MonitorAgent's real code_run dispatch can use SpoolAnalysisSessions in pilot
mode. The task-side spool only accepts fixed start/read/close operations tied
to one run_id; it cannot select host commands, image, mount or container args.
The trusted host uses PilotDockerToolPort, reusing the prior certified
DockerToolPort UTF-8 script/receipt/session implementation. It pins an exact
image ID and named Task volume. The diagnostic container has /app mounted RO,
network=none, read-only root, dropped capabilities, no-new-privileges, and
independent writable private/home/tmp/cache/output; it has no Docker socket.
The host journals acceptance before execution; a duplicate or uncertain
request is not executed again. Cancellation and close check container removal.
The ordinary AnalysisSessions Popen path remains only when pilot mode is off.
When pilot mode is on, a spool integrity failure is latched and prevents
subsequent Monitor actions rather than being returned as an ordinary tool
failure. Any source update observed during a command is marked
version_uncertain; a return-time tree hash is not asserted to cover the full
execution interval. Private scratch diffs are attached to results.
Tests used the real Fyne and Kitex images and Docker named volumes: a fake
Task wrote v1 and v2 into /app, the real Monitor dispatch read each version,
direct Supervisor write to /app failed, and a private Go test compiled and ran.
Separate T/S image volumes were initialized from the same images and had equal
full content/type/mode manifests: Fyne 2787 entries, SHA256

Projection and provider evidence
================================
root_records_v1 remains default-off. Before History mutation, the pilot now
uniquely archives full source History, actual projected History and manifest,
reads all three back, rechecks current handoff and source History, and writes
and reads back a commit record. A source locator/hash is present in the
ledger. Archive/commit mismatch or failure latches ProjectionIntegrityError;
stale handoff does not become a success. A pilot-only provider pre-send hook
captures the actual assembled request before transport and checks that a
pending projected ledger is visible. Capture failure blocks transport. The
accepted request_usage clears pending visibility. A pilot-only runtime option
disables the Monitor provider's extra ambiguous-recovery batch. Normal mode
keeps the preexisting behavior.

Task/evaluator isolation issue found
===================================
Harbor trial._agent_env_mounts unconditionally bind-mounts the task package's
verifier_dir into the agent container even with verification disabled. Simply
passing --disable-verification would expose tests. pilot_task_package.py now
materializes a fresh agent-phase package with identical public instruction,
task.toml and environment, but an empty tests mount and no solution. Harbor's
real Task.is_valid_dir(..., disable_verification=True) and Task instruction
equality passed for both target tasks. The original full package is retained
only for a future post-agent evaluator phase. This materialization does not
yet implement that separate evaluator execution or its barrier.
