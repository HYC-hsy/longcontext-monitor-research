Let me start by understanding the problem clearly:

### Phase 1.3: Problem Explanation

The issue is about **incorrect cross-reference resolution** in Sphinx's Python domain for the `:type:` and `:rtype:` info fields.

**Key Details:**
- **Classes involved**: `mod.A` and `mod.submod.A` (two classes with same name in different modules)
- **Directives**: `:param`, `:type:`, `:rtype:` fields and `py:currentmodule`
- **Error messages**: "WARNING: more than one target found for cross-reference 'A': mod.A, mod.submod.A" at lines 28 and 43
- **Wrong behavior**: When `py:currentmodule` is `mod.submod`, unqualified name `A` in `:param A a:` and `:rtype: A` incorrectly resolves to `mod.A` instead of `mod.submod.A`
- **Correct behavior**: Explicit xref roles like `:py:class:`A`` correctly resolve to `mod.submod.A` without warnings

**Root Cause**: The implicit xrefs created by `:type:` and `:rtype:` use a different (incorrect) lookup algorithm that searches all modules instead of following the proper module hierarchy (current module → parent modules).

### Phase 1.4: Steps to Reproduce

1. Create two classes with the same name in different module levels: `mod.A` and `mod.submod.A`
2. Set `py:currentmodule` to `mod.submod`
3. Use unqualified name `A` in `:param A a:` or `:rtype: A`
4. Observe: False ambiguous warnings and incorrect resolution to `mod.A` instead of `mod.submod.A`

## Implementation Complete ✅

I've successfully implemented the fix for the false ambiguous warnings in `:type:` and `:rtype:` fields.

### The Fix
**Single line change** in `sphinx/domains/python.py` at line 95:

```python
return pending_xref('', nodes.Text(text),
                    refdomain='py', reftype=reftype, reftarget=text, refspecific=True,
                    **kwargs)
```

Added the `refspecific=True` parameter to make type field references use module-aware search (searchmode=1) instead of global-first search (searchmode=0).

### Why This Works

**Root Cause:** The `type_to_xref()` function created cross-references without the `refspecific` attribute, causing the resolver to search globally first and find multiple matches when the same class name exists in different modules.

**Solution:** Adding `refspecific=True` makes type annotations respect the `py:currentmodule` directive, just like explicit `:py:class:` role references do.

**Consistency:** This aligns type field behavior with:
- Explicit role references (line 275: `PyXRefRole.make_xref`)
- Dot-prefixed references (line 1050)
