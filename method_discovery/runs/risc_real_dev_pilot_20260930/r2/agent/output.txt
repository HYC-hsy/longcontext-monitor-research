## Technical Decisions & Rationale

### 1. Separate cep/sep Packages
- **Why**: Different middleware chains for client vs server streaming
- **Benefit**: Type safety prevents mixing client/server endpoints

### 2. TailOption vs Direct Stream Options
- **Why**: Allows per-call customization without polluting global client options
- **Benefit**: Flexibility for connection pooling, URL overrides, timeouts per stream

### 3. Thrift Fallback Guards
- **Why**: TApplicationException uses unary message framing incompatible with streaming
- **Benefit**: Prevents protocol violations and confusing error messages

### 4. Composite Protocol String()
- **Why**: TTHeaderStreaming combines TTHeader base protocol with streaming flag
- **Benefit**: Clear debugging output shows both protocol layers

### 5. Frame Validation Hex Dumps
- **Why**: Binary protocol errors are hard to debug without raw data
- **Benefit**: Immediate diagnosis of frame corruption or protocol violations
