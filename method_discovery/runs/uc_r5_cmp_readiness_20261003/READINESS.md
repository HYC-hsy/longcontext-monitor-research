## Budget and isolation

`BUDGET_AND_COST.json` gives the proposed 180 Task turns and 10,000-second integration ceiling, plus actual profile/default-derived request, context, retry, completion and launcher limits. These are ceilings, not duration estimates. A 7,200-second task.toml agent timeout scaled by `10000/7200` and a 10,900-second launcher timeout are the existing runner's proposed control path, not changes made here. Token buckets, automatic source reads, artifact I/O, tool time and Task blocking must all be accounted for; unavailable exact timings are marked missing or proxy rather than manufactured. `code_run` is a general local execution tool, not a complete OS sandbox. The intended container uses no task network and a Unix-socket inference path, but its current live mount/image isolation remains unverified while Docker is unavailable.

## Results policy and input boundary

`RESULT_LEDGER_SCHEMA.json` preserves the runner's `valid`, `validation_errors` and `exception_info` without using `valid=false` alone to discard a candidate. It separates candidate crash, non-adoption, invalid tool arguments, ordinary budget exhaustion, external failure, identity/isolation failure and ordinary task-test failure. `allow=false` is not inferred from a missing allow log. No native score may select follow-on slots or prompt revisions; no record-level rerun is preauthorized.

Condition labels, allocation, historic failures, hidden tests and solution identity are research-side only. The actual Task input transformation is saved separately from the original instruction; the Monitor original task should receive those same actual bytes. Normal opaque paths, original tool names and existing audit facts are not automatically contamination. Deployed provider-ready boundary proof is still missing, so this report does not assert online input non-leakage.
