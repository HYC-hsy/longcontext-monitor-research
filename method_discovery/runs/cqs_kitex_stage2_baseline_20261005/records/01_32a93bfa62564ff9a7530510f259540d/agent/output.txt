## Key Design Decisions

### 1. Endpoint Architecture
- **Chose:** Separate CEP/SEP files with streaming middleware support
- **Rationale:** Clean separation of concerns, extensible for future protocols
- **Alternative Rejected:** Monolithic endpoint file (poor maintainability)

### 2. Codec Fallback Strategy
- **Chose:** Remove codec type restrictions entirely
- **Rationale:** Maximizes performance regardless of configuration
- **Trade-off:** Slightly more complex error handling, but better user experience

### 3. Protocol Enumeration
- **Chose:** Pipe-separated string representation for combined protocols
- **Rationale:** Human-readable, grep-friendly, supports future protocol combinations
- **Alternative Rejected:** JSON encoding (unnecessary complexity)

### 4. Frame Validation
- **Chose:** Configurable maxReadSize with hex dump on error
- **Rationale:** Balances security (DoS prevention) with debuggability
- **Security:** Prevents memory exhaustion attacks

### 5. Client Options API
- **Chose:** Separate option files for unary/stream/ttstream
- **Rationale:** Clear organization, easy to discover related options
- **Follows:** Existing pattern in `client/option.go`
