## Key Design Decisions

### 1. Protocol Default: PurePayload → Framed
**Rationale:** Framed provides buffering and better flow control, reducing the risk of message corruption in high-throughput scenarios. The old PurePayload default assumed users would explicitly configure protocols, but Framed is a safer starting point.

**Implementation:** Smart `SetTransportProtocol()` logic ensures that:
- Incompatible protocols (HTTP, HESSIAN2) replace Framed
- Compatible protocols (TTHeader, GRPC) compose with Framed using bitwise OR
- All existing tests pass without modification to test logic

### 2. Explicit Conversion Methods
Even though `UnaryMiddleware` and `Middleware` are type aliases, we provide explicit `ToMiddleware()` and `ToUnaryMiddleware()` methods. This:
- Makes API intent crystal clear
- Facilitates future refactoring if types diverge
- Improves code searchability and documentation

### 3. Separate cep/sep Packages
Rather than adding `ClientStreamEndpoint` and `ServerStreamEndpoint` to the main endpoint package, separate packages provide:
- Clear namespace separation
- Easier tree-shaking for clients that only use one mode
- Future extensibility (e.g., bidirectional streaming package)
