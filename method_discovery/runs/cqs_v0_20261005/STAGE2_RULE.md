# Conditional Stage 2 / optional Stage 3 — research decision only

`execution_authorized=false`. This file does not create a slot ID, manifest, or executable authorization.

After both Stage-1 candidate records, the main research thread inspects raw control actions, provider inputs, CQS surfaces, public feedback, working/History, terminal artifact binding and cost. If both show a clear failure such as no useful continuity effect, predominant reliance on a completion ledger, sticky obsolete concern, inability to retire resolved concern, or marked cost growth without a new control chain, stop as NO-GO after those two. This judgment is semantic and is never made by the runtime or replay script.

If at least one candidate record shows a clear `carried control issue → new feedback → revise/retire question → new decision/measurement/control` chain, the main research thread may separately authorize exactly one fresh contemporaneous CFS+DCM baseline with CQS off on the task showing the clearest signal. It must not reuse History/workspace or interpret historical baseline records as a formal effect estimate. The third slot's identity and authorization are deliberately not allocated here.

A fourth trial or replicate requires another explicit research authorization and is only considered if tasks conflict, the third record remains attribution-limited, or CQS is being considered as a finalist. A later paired/multi-seed confirmation batch is separate. No automatic Stage-2/3 execution or outcome-based rerun is permitted.
