# ASE-v0 zero-model implementation

Parent archive: `6915008f211431bf58253cd876e093a96b6ca0f7`. CQS-v0 implementation source: `cab01032c82d817b1b9ba28e18ef2504bd4a87a7`. This is a new, default-off candidate; no scientific session or native evaluation is authorized by this directory.

The switch is `monitor_adaptive_supervisory_environment`. It requires the existing DCEC/PATH/CFS/DCM manual continuous path, with CQS-v0, EIS, RSH and the old root-scope split off. It changes only the Supervisor's context and review-local release wording; there is no new tool, model call, verifier, requirement graph or semantic parser.

At initialization the compact ASE system guidance asks the same Supervisor to read `task/original_task.txt`, inspect the pristine task workspace and write its own short `monitor/reference.md` after any useful ordinary investigation. The file is a revisable interpretation, not a progress or completion ledger. Its bounded request-local surface is at most 3600 characters, including authority warning and full-file locator. On overflow it mechanically preserves both head and tail and marks the omitted middle. Missing/empty/unreadable states have no invented reference content. Every prepared surface records source/visible characters, truncation, byte SHA-256 and rendered size; `ase_context_injected` records the successful-response exposure with hashes of reference, continuity, CFS and their composed active context.

`monitor/working.md` remains a private writable scratch/continuation note but is not automatically supplied in ordinary ASE requests. The existing compaction path still writes only the working note. ASE's active composition is reference → optional local continuity → current CFS Situation. The short local continuity retains the latest submitted intervention through successive follow waits; follow changes only the current awaiting context. A completed patrol releases it. No task status or requirement identity is inferred.

ASE reuses DCM's first-attempt interception and independent-model-turn confirmation for patrol and root resolve, but substitutes a short mechanical reconsideration receipt. It does not demand an observation before confirmation. Existing freshness, action, follow, intervention, cadence and budget paths remain unchanged. The system guidance is 1969 characters; the reconsideration guidance is 283 characters. The seven tool names and schemas are unchanged.

Mechanical events: `ase_reference_surface_prepared`, `ase_reference_mutated`, `ase_reference_mutation_failed`, `ase_context_injected`, `ase_continuity_updated`, `ase_continuity_cleared`, `ase_continuity_surface_injected`, `ase_release_attempted`, `ase_reconsideration_boundary`, `ase_post_boundary_tool`, `ase_release_confirmed`, `ase_release_abandoned`, `ase_review_ended_with_boundary_pending`, and `ase_exact_duplicate_observation_call`. They contain source/action locators, hashes, counts, model-turn relation and bounded payloads, not adequacy verdicts. Follow telemetry includes consecutive count, Task-turn age where available, and requested `after_turns`. Exact repeated code strings and canonicalized file-read ranges are audit-only.

Legacy CFS/DCM/CQS and ASE-disabled code paths retain their previous branches. Focused legacy tests are included in the offline run, including provider-ready DCEC-off equality against its frozen parent. This is engineering compatibility evidence, not a scientific result.

Known limits: the runtime does not enforce reference quality or stop the Supervisor writing progress there; a middle passage omitted from the surface requires an explicit `file_read`. The bounded continuity carries the most recent intervention and follow, not a history or semantic state. Exact duplicate telemetry does not equate semantically equivalent commands. Provider exposure events use the conservative successful-response boundary; a failed transport's actual remote consumption is not inferred. No Fyne, Kitex or Sphinx trial was run.
