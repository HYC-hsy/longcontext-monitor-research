# ASE-v0 zero-model implementation

Parent archive: `6915008f211431bf58253cd876e093a96b6ca0f7`. CQS-v0 implementation source: `cab01032c82d817b1b9ba28e18ef2504bd4a87a7`. Initial ASE implementation: `dfbd8e8116d3414fa028d8a21b13a68b4c28cb17`; pre-trial cleanup: `5ab7d83ab6bb5db2ddb90251fd7b75ad1ca0f7c3`. This is a default-off candidate. This directory does not authorize a scientific session or native evaluation.

`monitor_adaptive_supervisory_environment=true` independently installs the mechanical `SituationState`, `LocalContinuity`, `ReconsiderationBoundary`, ASE active-context composition, and same-session root routing. It does not require the DCEC, PATH, CFS, DCM, or verification-loop configuration switches. ASE is exclusive with those historical candidate switches and research view/intent. When ASE is false, the legacy candidate paths retain their original logic.

The provider-visible tools are the original seven-tool `MONITOR_TOOLS` schema: `file_read`, `file_write`, `file_patch`, `code_run`, `wait`, `intervene`, and `allow_complete`. ASE does not expose verification metadata on `code_run` or result/disposition fields on `wait` or `allow_complete`. There is no added tool, model stage, verifier, requirement graph, or semantic parser.

At turn-zero initialization, the same Supervisor is guided to read `task/original_task.txt`, inspect the pristine workspace, and use ordinary private file tools to write its own short `monitor/reference.md` after any useful investigation. Before the first initialization wait can actually execute, the file must exist and contain non-whitespace text. An absent or empty reference returns mechanical tool feedback and leaves the review open; an evidenced intervention is not blocked, but does not waive the later first-wait requirement. The runtime neither writes reference content nor evaluates its task semantics. Audit events `ase_reference_initialization_pending` and `ase_reference_initialization_ready` record this adoption boundary.

The reference is a revisable Supervisor interpretation, not a progress/completion ledger or verified truth. Its request-local surface is at most 3600 characters, including authority warning and full-file locator. Overflow mechanically preserves head and tail and marks the omitted middle. Missing/empty/unreadable states have no invented interpretation. Prepared and successful-response exposure events record source and visible characters, truncation, byte SHA-256, rendered size, and hashes of the reference, continuity, Situation, and composed context.

`monitor/working.md` remains writable private scratch and continuation state, but is not automatically supplied as ASE's task reference. Pre-compaction continuation writes only the working note, not `reference.md`. Ordinary ASE active context is ordered Reference, optional Local Continuity, then fresh CFS Supervisory Situation. `LocalContinuity` retains the most recent submitted intervention anchor across follow waits. A follow uses the natural preceding model rationale as its short awaiting context; it does not require a structured reason field. An executed patrol clears the local episode. It is prior control context, not task truth.

ASE reuses DCM's independent-model-turn mechanical release boundary with a short reconsideration receipt, not DCM's epistemic guidance. An ordinary patrol with inactive Local Continuity executes immediately. The first patrol with active Local Continuity is held for one additional model turn; a repeated patrol can then execute. A current root `allow_complete()` always gets the same one-time reconsideration before an independent repeated call can execute. No extra observation is required. The root uses the same persistent Supervisor History and ordinary `working.md`, independently of verification-loop; it does not create `root_working/` or add the old root system prompt. Existing handoff freshness, cadence, intervention, action, and budget rules remain in force.

Mechanical audit events include `ase_reference_surface_prepared`, `ase_reference_mutated`, `ase_reference_mutation_failed`, `ase_context_injected`, `ase_continuity_updated`, `ase_continuity_cleared`, `ase_continuity_surface_injected`, `ase_release_attempted`, `ase_reconsideration_boundary`, `ase_post_boundary_tool`, `ase_release_confirmed`, `ase_release_abandoned`, `ase_review_ended_with_boundary_pending`, and `ase_exact_duplicate_observation_call`. They preserve action/source locators, hashes, bounded payloads, follow count, available Task-turn age, requested `after_turns`, and exact duplicate observation counts; they do not contain adequacy verdicts. Provider exposure is counted at the conservative successful-response boundary, not at request assembly.

Known limits: non-empty reference formation is mechanical, not a quality or truth check; the runtime does not stop the Supervisor from later writing progress claims there. A middle passage omitted from the bounded surface requires an explicit `file_read`. Continuity carries the latest intervention/follow, not a full history or semantic state. Exact duplicate telemetry does not equate semantically equivalent commands. A failed transport's possible remote consumption is unknown. Deterministic tests are engineering evidence only; no Fyne, Kitex, Sphinx, real Supervisor/Task Agent, or native verifier trial was run for this correction.
