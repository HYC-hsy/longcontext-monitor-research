#### 3. Priority-Aware Flow Control (`flowcontrol.go`)

**Enhanced onRead method:**
```go
// onRead is invoked when the application reads the data. It returns the window size
// to be sent to the peer.
func (f *inFlow) onRead(n uint32) uint32 {
    return f.onReadWithPriority(n, 128) // default normal priority
}

// onReadWithPriority is invoked when the application reads data from a stream.
// It returns the window size to be sent to the peer, adjusted based on stream priority.
// Priority range: 0-255 (lower value = higher priority)
//   High priority (0-63): More aggressive window updates (threshold: limit/8 to limit/4)
//   Normal priority (128): Standard behavior (threshold: limit/4)
//   Low priority (192-255): Conservative window updates (threshold: limit/3 to limit/2)
func (f *inFlow) onReadWithPriority(n uint32, priority uint8) uint32 {
    f.mu.Lock()
    if f.pendingData == 0 {
        f.mu.Unlock()
        return 0
    }
    f.pendingData -= n
    if n > f.delta {
        n -= f.delta
        f.delta = 0
    } else {
        f.delta -= n
        n = 0
    }
    f.pendingUpdate += n
    
    // Priority-based threshold calculation
    // Lower priority value = higher priority = more aggressive updates
    // High priority (0-63): threshold = limit/8 to limit/4 (send updates at 12.5%-25%)
    // Normal priority (128): threshold = limit/4 (send updates at 25%)
    // Low priority (192-255): threshold = limit/3 to limit/2 (send updates at 33%-50%)
    priorityFactor := uint32(priority)
    if priorityFactor < 64 {
        priorityFactor = 64 // cap at limit/8 for highest priority
    }
    threshold := f.limit * priorityFactor / 512 // maps 64-255 to limit/8 through limit/2
    
    if f.pendingUpdate >= threshold {
        wu := f.pendingUpdate
        f.pendingUpdate = 0
        f.mu.Unlock()
        return wu
    }
    f.mu.Unlock()
    return 0
}
```

## 🔑 Key Implementation Details

### Target 7: Priority-Based Flow Control

**Priority Range:**
- **0-63:** High priority → Window updates at 12.5%-25% threshold (2x faster)
- **128:** Normal priority → Window updates at 25% threshold (default)
- **192-255:** Low priority → Window updates at 33%-50% threshold (2x slower)

**Algorithm:**
```go
// Priority-based threshold calculation
priorityFactor := uint32(priority)
if priorityFactor < 64 {
    priorityFactor = 64  // cap at limit/8 for highest priority
}
threshold := f.limit * priorityFactor / 512  // maps 64-255 to limit/8 through limit/2

if f.pendingUpdate >= threshold {
    wu := f.pendingUpdate
    f.pendingUpdate = 0
    return wu  // Send WINDOW_UPDATE frame
}
return 0  // Wait for more data
```

**Integration Points (4 call sites):**
1. Client updateWindow() - line 787 in http2_client.go
2. Client handleData padding - line 838 in http2_client.go
3. Server updateWindow() - line 529 in http2_server.go
4. Server handleData padding - line 580 in http2_server.go

All calls changed from:
```go
s.fc.onRead(n)  // Old: no priority awareness
```

To:
```go
s.fc.onReadWithPriority(n, s.priority)  // New: priority-aware
```

**Backward Compatibility:**
- All streams default to priority=128 (normal priority)
- Existing code sees no behavior change
- Priority can be set via future API enhancements
