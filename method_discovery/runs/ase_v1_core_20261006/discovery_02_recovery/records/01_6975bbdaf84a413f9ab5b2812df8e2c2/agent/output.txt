// Header represents RPC metadata in header
type Header map[string]string

// Trailer represents RPC metadata in trailer
type Trailer map[string]string

// ClientStream represents a client-side streaming interface
type ClientStream interface {
\t// SendMsg sends a message to the peer
\tSendMsg(ctx context.Context, m any) error
\t// RecvMsg receives a message from the peer
\tRecvMsg(ctx context.Context, m any) error
\t// Header returns header metadata from the server
\tHeader() (Header, error)
\t// Trailer returns trailer metadata from the server
\tTrailer() (Trailer, error)
\t// CloseSend closes the send direction
\tCloseSend(ctx context.Context) error
\t// Context returns the stream's context

## Critical Issue Resolved: Stream vs ClientStream Interface Conflict

### Problem
After Target 1 changes, `client/stream.go` attempted impossible type assertion:
```go
if cs, ok := s.stream.(streaming.ClientStream); ok {
    return cs.Header()  // IMPOSSIBLE
}
```

**Root Cause:** 
- `Stream` interface (deprecated): `RecvMsg(m interface{}) error`
- `ClientStream` interface (new): `RecvMsg(ctx context.Context, m any) error`
- Same type cannot implement both due to conflicting method signatures

### Solution
1. Created `StreamMetadata` interface in `pkg/streaming/streaming.go`:
   ```go
   type StreamMetadata interface {
       Header() (metadata.MD, error)
       Trailer() metadata.MD
   }
   ```
2. Updated `client/stream.go` to assert to `StreamMetadata` instead of `ClientStream`
3. Underlying transport layer (`pkg/remote/trans/nphttp2/stream.go`) already implements these methods

**Result:** ✅ Build successful, all tests pass
