# Per-slot pre-inference gate (specification; no launcher)

The checklist is **not executable**. `execution_authorized=false`; the existing runner's `apply_experiment_manifest()` does not interpret that field, so this directory intentionally contains no runner-compatible top-level `runs` list. Separate main-thread authorization and a frozen executable manifest are prerequisites. No model hello may be used to fill unknowns.

Before the **first inference request for each slot**, record a signed/hashed gate receipt and halt without starting that slot if any required fact fails:

1. Check the slot's unchanged opaque ID, position and `not_started` status against `SLOT_DRAFT.json` SHA-256 `ae7b7e93f79886be1e7801e358e0bcafbaa160071b33afe03dc67de25ee842fa`. Check its planned live root and output/job roots are unused. Never substitute an ID or skip a failed slot.
2. Check actual task cache/proposal row, instruction, task.toml, initial task tree and existing local image ID/RepoDigest/architecture against the per-slot checklist. Proposal `source_revision` is not assumed to be `/app` Git HEAD. Re-read the actual image and filesystem/mount identity at launch, not just the older L2 precheck.
3. Set `GA_HOST_ROOT` to the slot's private `launch_<group>/GenericAgent-main` and select the sibling `monitor_config/models.local.json` through the **existing** runner `load_profile → build_bundle(monitor_profile_path=...)` path. Verify runner-scoped source tree hash `21bca97c077317d11467a28405ecd2abdb4aa8a0f3c97b74574626cba5be30c4`, implementation commit, exact private profile SHA, generated deployed `models.local.json` allowlisted fields, candidate code file manifest, task profile identity and harness SHA before starting. Profile secrets and gateway configuration remain private; publish only non-secret allowlisted values and hashes. Do not confuse per-group bundle-total hashes with code drift.
4. Inspect the **actual planned trial mount map and launch-time container**: task network disabled, only the prescribed inference/telemetry Unix socket, expected `/app`, Python runtime and frozen source mounts; no `/tests`, hidden verifier, solution, old trajectory/checkpoint, condition assignment, precheck research scripts, `guarded_worker`, scripted `_request_once`, secret-bearing task mount or unexpected host path. A clean raw image alone does not satisfy this check. Preserve the raw mount/container receipt. `code_run` is not an OS sandbox; report its real workspace/container access.
5. Read back the actual Harbor/adapter Task input and the Monitor's copied original task from the **launched deployment entry** and compare byte hashes to the slot's prepared input; record the established `ENVIRONMENT_NOTE` transformation separately from the original instruction. Do not add historical bug hints, case labels or study answers. A readback from the older L2 scripted adapter is prior evidence, not a substitute for this per-slot check.
6. Confirm common DCEC/working view/window, treatment two-key mapping, max turns/deadline, retry/timeout/context/cache settings and mutually exclusive historical switches. Capture the real provider-ready first request and tool schema **before it is sent**, with research metadata excluded. Actual service-reported model identity and tokens are not available until responses; leave null now.

There is a practical launch-boundary gap: the frozen runner builds its bundle and starts Harbor inside one `run_proof()` call. This document does not pretend that a host check before that call proves later dynamic mounts and input bytes. A future authorized deployment must expose a fail-closed check at that boundary or stop before first inference; if it cannot, keep the slot `not_started`/gate-failed and report the missing capability, rather than silently weakening the gate. No production, candidate or runner source was changed here.

For a failed gate, preserve slot identity, fact/error, timestamp and any local evidence; do not launch it, rerun it, assign a replacement or skip to the next condition without a new main-thread decision. An explicitly wrong configured model/image/task is an identity failure. A configured model match is not an observed service-model match: if a later response reports a different model, retain raw evidence and pause; if the service does not report an identity, record `unobserved`, not `matched`. Token and final artifact fields remain post-run unknowns. Ordinary task failures and low scores are not gate failures.
