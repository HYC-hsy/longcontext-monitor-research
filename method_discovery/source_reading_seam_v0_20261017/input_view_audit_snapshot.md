# 54 次输入来源诊断：独立审计与设计约束

2026-10-17。归档：52f2b5314c7861eb098ef14126c526bde89a85a4；冻结运行：e42c71b7e040a7cff55ea244f89a4c06800e8f6a。

## 结论

这轮没有发现需要先修复的输入投影错误。它更像一个有效的机制诊断：同一 D1 提示，改变可见信息组合，输出确实改变，但没有出现稳定获胜的视图。不能据此立即部署“删分析”或“删记忆”，也不能认为多加一个提问者就解决了问题。

## 实验究竟做了什么

六个已暴露的历史检查点，每个三种输入、各重复三次。F 是原完整 D1 输入；EB 保留原任务、记忆银行、命令和工具结果，去掉外层 Agent Analysis 与 Terminal Output.content；E 在 EB 基础上再移除银行。总共 54 次独立 Phase 2 请求。没有 Phase 1、Task 续跑、原生评价或提醒真实投递。

F/EB/E 各 18 次，提醒分别 15/5/10，沉默分别 3/13/8。这些是输出形式，不能作正确率。

独立对照实际请求：六份 F 与上一轮 D1 完全一致；三次重复的同视图提示一致；任务、系统提示、D1 后缀和保留的命令/工具结果一致；记录配置一致。详细校验与证据见同目录 integrity。三个语义分组分别保存全部请求与输出、原文定位和局限。

sampler 235 的 E 第一次是一个值得保留的正向例子：它区分了公共 API 的 density 契约与算法内部 log-density 表示。其余沉默不证明也理解了这种区分；该建议本身也不是运行过的补丁。

SQLite 中 Task 已经表示要尝试 minimal tools；所以删分析后的沉默不能统一算漏报，也不能统一算正确。这里同时涉及建议是否有用、是否重复、是否夸大依据。

## 必须保留的解释边界

1. E/EB 并非“纯客观事实”。checkpoint、file_write 等工具参数中仍包含 Task 写的解释，代码注释也可能携带猜测。投影按字段操作，不能自动识别所有语义来源。
2. F→EB 同时改变叙述、意图与大量文本长度。它没有隔离某一句错误叙述的因果贡献。
3. EB→E 只在去掉外层叙述这一条件下比较银行。没有第四个“保留叙述、移除银行”条件，不能推断完整交互效应。
4. 六个检查点来自四个任务家族，三次重复不是独立任务。它们已用于方法发现，不是留出集。
5. 没有 Task 行为和最终产物变化；不能报告任务成功率提升。
6. 上述语义判断来自人工逐条审读，不是自动评分类别的数学认证。

## 对设计的实质约束

这轮削弱的是“清理输入本身就足够”的假设。它没有否定原要求或工具观察的重要性，也没有证明新的复杂状态机制会有效。

下一候选需要同时满足三件事：
- 保留上下文中有用的解释、计划和帮助机会，而不是只靠删信息降低输出。
- 将解释当作可修订判断；来源、适用对象和观察范围不能被一句有说服力的总结替代。
- 让修订真正改变建议，最终改变 Task 的测量、实现或验证行为，而非只增加更多引用。

研究上优先比较“同一判断如何随依据更新”的算法结构，而不是角色数量。是否采用持续判断对象、局部修订或主动取证，仍需邻近论文/源码和反例约束。不能把这些待验证方向写成该实验已经证明的答案。

暂不建议重跑同一 54 次，也不建议直接给全部 Task 接入提问版。先完成候选技术规格，保留本批正反例，再做少量有明确区分目的的新比较；原版 PMA 和简单反思/原要求重放应继续作为对照。
