Exact adaptation contract
- Only PoS belief/consistency/progress role callers use
  pos-role-json-object-fence-v1. A plain response is passed byte-for-byte
  unchanged to the original parser, even if invalid. For an entire response
  matching exactly one triple-backtick JSON (or unlabeled) fence, with LF or
  CRLF line endings and only spaces/tabs/CR/LF outside, the adapter checks
  that the interior is exactly one strict JSON object. It then removes only
  the opening/closing fence and allowed outer whitespace. The interior string
  is not reserialized or repaired. Duplicate keys, nonstandard constants,
  nonfinite numbers, non-object roots, trailing data, partial data, multiple
  fences and explanatory prose are not accepted as the new path. They pass
  unchanged to the original parser and its original bounded correction.
- The provider's public response is retained in pos_role_response.response.
  A separate pos_role_json_adapter event has the contract version, role/call
  identity, raw/parser strings and SHA-256, transform and removed boundary.
  Original upstream raw_response fields mean the string actually handed to
  their parser, which may be adapted; they must not be called provider-raw.
  Hidden thinking is excluded from this output and public archive.
- PoS role configuration COPIES now explicitly use thinking_type=disabled,
  temperature=0, belief max_tokens=4096, consistency/progress=512, and zero
  transport retry. Model remains claude-opus-4-8 with the previously frozen
  private route/profile bytes. These settings were NOT present in the prior
  failed live probe. Task settings and native tool behavior are unchanged.
  No unverified response_format parameter, tool-forced JSON, extra LLM or
  vendor modification was added. See the new manifest config/config_sha256.
