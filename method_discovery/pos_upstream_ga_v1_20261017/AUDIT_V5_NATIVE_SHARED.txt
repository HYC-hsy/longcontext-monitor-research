Method and host semantics
-------------------------
One GA decision plus its ordered tool batch is one joint-action PoS
transition. Actual tool IDs/names/arguments/order and executed/rejected/
not-executed states are action metadata; corresponding raw public results
are observation and independent host receipts. A handler existence check
determines unknown-tool rejection; this is not a complete mounted-schema
permission check and does not change GA dispatch permissions. Eight tools
inside one decision are one scored batch; K=8 means eight scored decisions,
not eight tools. Unscored events are not synthetic zero-progress samples.
For code_run, null exit code, timeout, truncation or background status stays
as observed; a returned tool receipt is not a claim of process completion.

The last real tool result is submitted before PoS finish. A no-tool finish
records only public terminal content and runtime reason, not a fabricated
action, progress, recovery or success. Host CURRENT_TASK_DONE is a legitimate
runtime exit, not hidden evaluator success. Online success_known=false means
no authoritative success signal. Active recovery at termination remains the
last PoS core state; no fictitious recovered state is inserted. A PoS update,
export, archive or fsync error is an auxiliary failure; an already-known
Task terminal and tool receipt remain the host fact. Disk failure is not
promised to be recoverable. Failure after an accepted or acceptance-unknown
command never triggers an unrecorded replay or silent GA/PMA fallback.

The upstream goal interpretation remains fixed, observed/source_type labels
do not prove truth, Sentinel citation checks are not semantic entailment,
and the published E/A persistence tie favors epistemic. Recovery is Task
context, not an approval gate. Transport/profile, batch grain, GA model
interface and Task set differ from the paper; no paper-score claim follows.
