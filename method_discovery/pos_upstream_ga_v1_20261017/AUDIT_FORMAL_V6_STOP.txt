PoS-on-GA formal v6: stopped-run audit (2026-10-18)

Outcome
The authorized serial process ended with exit 1 after attempting task 2. Task 1,
nginx-request-logging (run pos-5439517d8b2d43fb), completed and received one
native evaluation with reward 1.0. Task 2, adaptive-rejection-sampler (run
pos-0231c24370734de0), was rejected by the exact audited-code-commit check
before Harbor, Task, PoS worker, provider HTTP, tools or evaluator started. Task
3 sqlite-with-gcov and task 4 write-compressor were not started. No task was
rerun. The second task has no score; it is not a 0.

Cause and chronology
The serial runner froze its authorization to the HEAD it read at launch,
5a0d9b6a9903118c314af9cdd24e04bf0ab9e087. While task 1 was active, a
subsequent evidence-only commit f5c7792c460b3ed16097ee0081f95f259239ea36
advanced HEAD. The only files changed between those commits were .gitattributes
and AUDIT_V21_PRELAUNCH.txt under this research directory; the runtime method
code did not change. Nevertheless the existing policy compares exact HEAD, so
task 2's verify_live_spec raised "PoS running code differs from authorized
commit". The serial runner removed task 2's one-use authorization and stopped.
The scheduling error was committing evidence during an active four-task batch;
the identity guard correctly prevented continuation. The earlier audit commit
and this stop are both retained; no old record was rewritten to conceal it.

This handoff adds only an archival script, public projections, hash index and
