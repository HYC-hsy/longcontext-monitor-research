-----

NativeClaudeSession. PMA/PoS role transports, provider parameters, prompts,
tools, task assets, and the default-off legacy path were not changed. No real

changes infrastructure response acceptance, not the PoS/PMA methods, and does
not establish the cause of any historical incomplete stream.

Three corrections
-----------------
1. NativeClaudeSession.ask appends an accepted strict response to assistant
history even if its legal public text contains !!!Error: or another historical
marker. The loop's final outcome uses complete_response_accepted before applying
the legacy text-marker failure heuristic. With the switch off, the old heuristic
remains. Synthetic text-only and text-plus-tool loop runs cover marker prefixes
and the historical interruption marker, history, tool count, and terminal type.

2. The strict sender checks the same fixed Task deadline and cancellation after
the required provider_response success receipt, before each buffered delivery,
and again after a resumed generator. ask checks again before history commit;
ask_stateless checks before returning. Late failures do not retry or dispatch
tools. The normal monitor-correction cancellation path still exists; a PoS
decision is not advanced, and a PMA normal actor_step is not sent. A response
chunk already yielded to a paused consumer may have been displayed, but is not
committed to assistant history or used for a Task action after late rejection.

3. Strict SSE parsing binds each active content block to the next sequential
nonnegative integer index (bool is not an integer index). Start/delta/stop with
missing, invalid, repeated or wrong index, duplicate start, or wrong block type increments parser errors and
cannot close an unrelated tool block. A malformed frame yielding zero parsed
blocks is classified from parser integrity, not converted to a retryable empty
transport response. All such index errors reject without an automatic retry.
Non-strict parsing retains the old behavior. This is not a general SSE rewrite.
