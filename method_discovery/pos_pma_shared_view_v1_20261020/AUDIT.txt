Implementation boundary
PMA Phase 1 runs first at the original trigger; the bank renderer selects once
and freezes entries, text, hashes, version and available input-source identities.
That selection enters PoS initialize/update and actual audit requests. PoS then
updates through its original candidate/audit/progress/recovery order. PMA Phase 2
uses the frozen render and final adopted PoS state; it may issue or withhold advice.
One temporary view is added to the ordinary GA request, with original history
and native tool pairing retained. The Task still owns actions and completion.
The new mode removes former complement-specific 16K/12K/90KB guards; this is
not a claim that provider context is unlimited. Updater and Phase 2 see selected
history; audit sees only projected citable tool fields under its original 6000
character per-step observation rule. Creation-time input provenance is not
sentence-level support. Task-only initial text is not a tool citation. See
DESIGN.md and REUSE_MAP.md for method versus host-adapter changes.
