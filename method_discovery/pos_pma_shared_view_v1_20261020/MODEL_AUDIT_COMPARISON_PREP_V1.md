## 统计、裁决与停止

先由两名不知道版本输出的审阅者对案例金标准、可引用范围及争议标签独立确认，再锁定裁决文件 hash；分歧保留 `disputed`，在主准确率分母外单列，不得看完模型输出改标签。R1–R4 属规划时可人工检查的合成事实，不代表真实任务观测。模型输出只按冻结程序解析结果及盲审语义判定，引用有效不等于问题语义正确。

- `wrong_rejection`：金标应允许，得到至少一个**语义上错误**的有效 issue。`wrong_acceptance`：金标应拒绝，却得到合法 `clean`，或有效 issue 均未指出金标问题；另记录是否误指别处。只在有可用最终审核结论时计算成对语义率，按案例、版本、金标及开发/保留分层报告。合法语义不同意见先标争议，不强行记错。
- `unusable`：JSON/字段失败、空响应或问题全被程序过滤；不算 clean、正确拒绝或错误放行。部分过滤仍有有效问题是 `issues`，另计过滤数/原因。全部计划调用作意向性分母，给出 clean/issues/unusable/未完成各自数量；主语义分母排除 unusable，但必须同时报告排除数，防止提高表面准确率。
- `wrong_citation`：模型给出不在本次可见集合的 ID/step、错误事件/字段、引文不在指定片段或跨片段；按输出 issue 计，另记录程序过滤和最终三态。A+B 精确引文与旧协议归一化不同，不能把旧协议的宽松匹配冒充同一规则。D7 及无模型的确定性 ID 正反例单独呈现，不混入语义正确率。
- `incomplete`：最终传输失败、截止/取消、必需捕获失败、未得到最终可用模型回答；与正常 `unusable` 分开。记录逻辑调用、各物理 POST、纠正请求、最终接受状态和未知尝试；部分回应不算已完成。成本按可观测各 POST usage、tokens、wall time 和可得实际金额逐项记录；未知计 unknown，不以逻辑调用替代物理计费。
