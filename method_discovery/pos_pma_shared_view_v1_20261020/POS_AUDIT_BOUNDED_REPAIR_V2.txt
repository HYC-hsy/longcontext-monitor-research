What changed
------------
1. In opt-in pos_pma_shared_view_v1, the shared audit system instruction now
replaces the conflicting legacy changed-only instruction. It inspects candidate
changes and also allows an unchanged retained claim to be challenged if this
step's explicit observation directly contradicts it. Silence is not disproof;
unsupported whole-graph objections and unsupported additions/deletions remain
disallowed. The old system instruction is still used when the flag is off.

2. The shared audit projection now maps a displayed source path to its actual
receipt field during projection. This preserves the full field path even for
result[0].stdout and content[0].output[0].text, the known event ID, and the
original field length used to compute each visible segment's offset. It no
longer parses result[0] as if it were a root dictionary key. Supplemental
history carries a known event ID too. Unknown identity is explicitly marked
unknown_fallback rather than silently discarding a known ID.

3. The opt-in evidence-ID hash binds case, event/fallback identity, original
step, field path, offset, length, and visible content SHA-256. A current-window
fragment and the identical supplemental-history fragment therefore have the
same ID, even after row reordering. Identical text at different offsets or
from different events has a different ID. ID membership is checked against
the present request, not against a prior-use blacklist: an old ID is valid if
its same fragment is still displayed. Missing/changed fragments cannot borrow
that ID. Explicit hash collisions still fail.

4. New-protocol quotes are tested as nonempty, contiguous substrings of the
selected visible fragment after JSON decoding. No case-folding, whitespace
folding, cross-field search or cross-fragment joining occurs. This is an exact
string comparison, not a claim about original network frame bytes. Legacy
evidence_step validation retains its previous normalization policy.

Direct test evidence and boundaries
-----------------------------------
The new tests in test_shared_view.py use a callback that reads the actual
constructed request and emits evidence_id responses directly. They check:
list result/content/nested paths and tail offsets; identical head/tail text at
different offsets; stable known-source ID after moving from the current window
into supplemental history and after row reorder; ID leaving the request;
content change; case/space/newline-mutated quotes; known versus explicitly
unknown event identity; an unchanged retained state challenged by this step's
visible move result; and an actual manager repair/reaudit request whose second
candidate_changes map names the replacement candidate, not the old one.

answers to IDs; these direct cases are independent of that test adapter.
