Contract
--------
The added system text distinguishes revisable belief_before, attempted action,
actual observation and candidate_after. It asks about specific state/relation/
gap/frontier changes, allows new observed facts and revision of older inference,
and warns that a copy does not establish source deletion or local success imply
broader completion. It also rejects unsupported additions, deletions and gap
closure. The diff is computed from the two actual state arguments at each audit,
including reaudit of a repaired candidate; it is a locator, not evidence.
Neither the original before/candidate nor trajectory is truncated by this diff.

The second commit assigns ev_<24 hex> to each actually displayed citable fragment.
Its hash input includes case identity, event identity when available (otherwise
the request-row position explicitly stands for unknown event identity), original
step, source field path, offset, length and fragment SHA-256. Different events
with the same text retain different IDs. Binding collisions raise an error.
The request displays the ID on its fragment, and a separate event records the
ID, step, event, path, offset, length and hash. The response must use evidence_id
and a short quote. The program first checks ID membership in this request, then
the quote against that one visible fragment, then the target against the existing
target set. Only then does it derive evidence_step for the existing internal
issue type. No whole-history lookup, text similarity, or cross-fragment joining.
Valid citation is provenance binding, not a semantic entailment proof.
Memory interpretations, task text, advice and old-state prose remain outside
the citable tool-source map. The existing clean/issues/unusable and one-finding
limit remain. Invalid siblings are counted and filtered, not changed to clean.
Transport errors still propagate; no extra model call or retry was added.

The issue challenged the new claim that /app/sqlite did not yet exist because

to future existence or Task completion. A second reviewer must adjudicate
whether the displayed listing was complete enough before any model comparison.
Mere novelty versus belief_before is never itself a rejection reason. This
historical model response is not replayed as if it had seen the new prompt.
D2, generic copy: receipt says a destination copy exists, with no source
deletion observation. Freeze before={source_present:true,dest_present:false},
action="copy src to dst", tool stdout="copied src to dst; src remains";
candidate={source_present:true,dest_present:true}. Expected: allow destination,
do not infer source gone. Counter-candidate source_present:false is unsupported.
D3, generic move/delete: receipt explicitly reports source removed; candidate
retains a contradictory source state. Freeze before={source_present:true},
action="move src to dst", stdout="move completed; src no longer exists";
candidate={source_present:true,dest_present:true}. Expected: one grounded issue
is allowed against retained source state, with the shown stdout as source.
D4, generic unsupported change: action requests creation but tool reports
failure. Freeze before={artifact_present:false,gap_open:true}, action="build",
stderr="build failed before output creation"; candidate={artifact_present:true,
gap_open:false}. Expected: unobserved addition or gap closure challenged.
D5, generic scope: local sandbox test passes while requirement covers deployed
service. Freeze task="service responds on deployed listener", before gap_open=true,
action="test local sandbox", stdout="sandbox test passed; deployment not tested";
candidate gap_open=false. Expected: do not close the broader requirement on
local-only evidence.
D6, generic stale gap: later tool receipt resolves one old uncertainty but a
separate active gap remains. Freeze before={gap_A_open:true,gap_B_open:true},
action="inspect artifact", stdout="artifact A exists; B not inspected";
candidate={gap_A_open:false,gap_B_open:true}. Expected: allow A revision while
preserving B, distinguishing revisable old inference from still-open duty.
D7, citation control: identical tool text in two events. Expected: distinct
IDs and derived steps/paths. An ID from a prior snapshot, an unknown ID,
non-tool memory prose, omitted middle text, or a quote spanning two fragments
must be rejected. A valid quote from one visible tool fragment can be bound.

These expectations are human-checkable scenario labels, not newly observed
model judgments. D1 is development material from a previously examined run;
D2–D7 are developer-constructed controls, also development material. There is
no independent held-out set in this delivery. The finite fake responses in
test_shared_view.py validate request construction and branching only. They do
not demonstrate that a real model will correctly decide D1–D6.
