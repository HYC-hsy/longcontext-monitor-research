## 1. global_mem究竟是什么

逐字读取当前 `GenericAgent-main/memory/global_mem.txt`：只有Global Memory L2标题。`global_mem_insight.txt` 是通用工具/SOP目录与规则，没有Fyne/FBR答案或此前实验结论。L4_raw_sessions是其中的文字指针；现有memory复制分支不递归复制L4目录，不能把指针存在当作历史会话已挂载。

规则确实包括Windows工具偏好、浏览器操作、搜索方式、规划SOP等。是否对Linux离线任务形成干扰是待实验问题，不是本轮已证根因。不能为了“干净”直接删掉既有Agent通用能力，也不能把它称作本研究的新机制。

`agentmain.get_system_prompt`调用`ga.get_global_memory`，后者把insight内容和固定结构写入任务提示；`ga.py`普通执行也会每10轮再次追加。global_mem.txt全文不是这段函数的自动输入。这些文件是任务Agent的固定行为条件，比较G0/G1/G2/M时必须一致且记录SHA。

此结论针对当前宿主文件，不能追溯证明每次历史运行都使用相同内容；需要旧运行副本SHA才可作历史一致性声明。

本轮按这些规则建立只读镜像清单，不调用build_bundle，因为后者会执行mykey.py并产生私密网关配置。清单含233文件、路径/大小/SHA/根仓库跟踪状态。它不把未跟踪文件自动add，也不复制运行材料。

233文件中207未由E:/LongContext根Git跟踪，既有文件未跟踪不等于本轮新增；其他嵌套仓库是否保存它们不是该指标范围。清单提供明确保存缺口，下一次冻结须保存实际内容，不能只保存哈希。

包含浏览器/GUI辅助、图片、PDF和旧研究模块，不能据文件存在断言模块已激活。`agentmain.py`有多项旧模块顶层导入；未经导入闭包验证就删除，可能使关闭的候选仍引发启动导入错误。此次不做“顺手清理”。

## 3. 插件和依赖影响复现

- `plugins/hooks.discover_and_load`按目录发现.py并导入；插件清单因此是行为配置的一部分。
- OTel由GA_OTEL_ENABLED及内容捕获/端点等变量控制；启用后需要OTel相关包。
- Langfuse插件根据配置初始化；隔离构建只输出指定模型配置，不能据插件文件存在认定它在线开启。
- project_mode有agent_before hook，激活依赖temp文件锚；干净副本不复制旧temp。存在插件不等于当前激活，但不能不记录。
- `pyproject.toml`主要是requests>=2.28等下限约束，不是精确锁文件；Harbor实际使用 `/opt/m4-runtime/python/...` 与ga-env/site-packages。宿主conda包列表不能冒充容器依赖锁。

完整复现需实际容器运行时包版本、Python身份和镜像digest。本轮没有启动/检查Docker，不编造版本，也不安装依赖。

## 5. 下一步建议：冻结当前输入，不做基线美化

建议先采取“行为保持的工程快照”，不是“删掉不喜欢的GA规则”：

1. 使用本轮明确清单完成未审附件/配置的秘密与历史材料筛查，核对任务/监察核心、接线与宿主启动依赖；仅保存核查过的内容。

3. 保存非秘密模型/开关/超时模板；实际凭证仍外部注入，gateway文件不入Git。
4. 形成一个明确标注“历史工程工作区快照，非新方法接受”的提交；它与本阶段研究工具提交分开。新checkout的确定性导入检查通过后，才能说源码可重建；镜像/依赖仍单列未验收。

这是下一步的收束方向，不要求再给监察者增加任何字段、提示或控制机制。当前没有必须改动在线知识的证据，因此没有擅自删改通用记忆。
