## 实施阶段及验收

### S1：材料导出与安全审查

只在新建的本地导出目录工作，原开发树和历史不重写。建立文件允许清单，确认源码依赖与第三方许可；对选入源码、文档、轨迹扫描密钥、认证头、用户名/绝对路径和其他敏感内容。日志先去除重复的完整请求快照，但保留有意义的输入、工具参数、结果、控制回执和顺序；任何删减都有说明，不把整理后的轨迹称为逐字完整原始轨迹。原文件保留在本地。

验收：可追踪源文件及 hash；无已知凭据；公开材料授权明确；大文件有体积清单；随机人工核对脱敏后证据仍支持审计结论。不上传整仓历史来规避历史秘密审查。

### S2：研究说明与代表性证据包

撰写当前研究入口，依据代码与轨迹而非旧规划拼接。区分研究目标、候选机制、工程已实现和真实有效性。保留负例供同行诊断。先提供 R8 完整脱敏决策过程和关键任务片段、人工参考干预序列，再视体积和许可决定是否附完整公开任务日志。每例明确哪些材料仅是事后评价，不能成为在线输入。

验收：外部读者能回答“研究什么、现在实现什么、观察到什么、尚未证明什么”；文档链接有效；代码入口和必要测试可离线检查；任何暂不可复现部分明确列出。

### S3：GitHub 发布

先由用户确定仓库账户/名称、private 或 public、邀请对象及原创代码许可选择。建议首先私有交流。创建独立干净 Git 历史，不推送当前开发仓库历史。上传前展示最终文件范围、大小、脱敏/许可结果，确认后才创建或推送远端；不自动邀请人员或改可见性。

验收：远端文件与审核导出包一致，README 阅读入口可用，不包含凭据/私有原始会话/未授权 benchmark 答案。记录导出源版本与发布 commit。
