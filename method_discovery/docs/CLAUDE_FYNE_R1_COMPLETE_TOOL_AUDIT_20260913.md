## 不能归咎于工具的实证问题

1. 查找App实现时，code_run显式使用 `grep -v "_test.go" | head -20`。后评分报app_test.go的dummyApp缺Metadata，且影响多个阶段。工具可以读测试，是模型自行排除；不能通过禁止过滤或强制全量读来冒充通用优化。
2. 17次code_run没有运行测试；24次file_read没有直接打开测试文件。唯一命令中出现_test.go是上述排除条件。不能说提示中没有关注测试，也不能说工具禁止读测试。
3. cursor150实际是 `go build ./... 2>&1` exit0，不是测试通过；151的最终陈述又混淆了若干已实现API。监察者最后仍allow。这是证据充分性和最终陈述核对问题，不靠给allow_complete增加表单解决。
4. 数据绑定虽有一次有效补改，事后仍有Rune/URI转换及读写失败。说明“指出一个缺口并修改”不等于完整行为支持。
5. 当前没有证据证明长脚本拖慢监察：全部code_run共约2秒。慢与高成本不能统一归为工具执行瓶颈。
