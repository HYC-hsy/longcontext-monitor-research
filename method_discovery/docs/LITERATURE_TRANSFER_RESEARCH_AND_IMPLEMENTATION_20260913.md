# 监察者的信息重建与选择性并发

## 研究结论

当前需要补齐的不是另一个笼统的“反思提示”，而是让同一监察者在每次决策中恢复合适的依据，并拥有与错误传播风险相称的执行控制。持续History解决对话延续，不自动解决信息选择；并行解决任务不必等每次审议，不自动解决建议赶不上执行。这两种缺口可以分别实验，也可能相互影响。

本轮将目标落实成两个可关闭候选：按需决策视图与有限暂停。它们属于阶段1原因发现后的机制尝试，不是最终方法冻结，不改变表示遗漏、错误闭合的研究问题。没有以下载仓库、通过单元测试或少量人工成功证明论文创新成立。

## 实际审计的相关工作

|工作|实际信息流/控制方式|可借鉴部分|不直接搬入的部分|
|---|---|---|---|
|PMA|原任务、近期轨迹、更新后的bank；同步维护后选提醒|把持久认识与决策输入连接；已有BM25实现|本轮不复制双phase整体，不把PMA换成研究母体|

|LangChain async-deep-agents|持续thread与后台任务生命周期、通知接线|稳定身份、可查询状态和交接语义|依赖LangGraph部署，不为复用少量逻辑迁移整个框架|

LivePlan §II-C 的“阻断”是拒绝尚未执行动作，再给建议；不是冻结整个系统等待全面验证。它的规则并不因为确定性就等于语义正确，其范围主要是流程、重复和停滞。源码`SWE-agent/sweagent/agent/agents.py`先`check_step_pre_emptively`，再按`should_block_and_refine`区分路径；`plan_monitor/monitor.py`暂存/回滚图和阶段状态。我们保留模型判断，复用独立表示代码，不移植这套领域分类器。[1]

Wink §3明确每k步启动后台观察，在结果可用时才注入；§7指出迟到指导可能在Agent自行恢复后变冗余。其单次/多次干预恢复率不是完整任务成功率，不能直接搬进本论文效果表。这是“并发不是免费正确性”的更直接证据；作者运行代码尚未确认。[2]

COCO描述保留诊断上下文的回滚与双向反思；其节点工作流、模型组合及复杂度论证不能直接外推至本系统。保留“监察也可能错，执行者反馈应修订判断”的机制启发，不引用其O(1)作为本系统保证。[3]

EmbodiedAct实际`handle.py:_pump`持续消费事件，L2通过create_task在后台运行；`steering.py`有合并重复疑点的队列。其pyproject写明`License to be added`，所以只读研究，不进行源码纳入。没有为了满足复用数量把不明许可、领域规则和第二模型强塞进来。[4]

## 实现一：按需决策视图

新增 `review_context(query='', after_correction=false, steps=8)`。模型主动调用，工程不按事件语义强制调用，也不逐轮自动推送完整packet。返回原任务、自然working.md、查询相关私有Markdown片段、近期公开的说明/动作/结果，以及上次纠偏。`after_correction=true`将窗口限制在最近一次提交之后，用于看执行者实际反应；默认最多8条公开事件，可改1–32条，不把它们谎称完整8轮。

私有记忆仍通过已有file_write/file_patch/code_run维护，没有新的obligation数组、ID或必填状态表。新增能力是按当前问题恢复相关认识与证据，而不是再造一份与真实文件不同步的bank。相对旧inquiry/focus：不维护另一个“调查对象生命周期”；统一提供根要求、自然笔记检索、上次输入和原始行为。旧工具默认关闭，但没有删除其历史实现。

原始公开JSONL仍为证据真源；视图只是一次工具返回，没有第三层持久语义分类。原始测试/代码不自动包含在窗口里，仍由监察者主动打开。每项有来源行号；这些是工具返回的可定位信息，不要求模型维护ID或语义索引。

直接复用的代码：

|文件|原作者对象|变更|
|---|---|---|
|vendor/pma_bm25.py|PMA memory/bm25_search.py|仅行尾规范化，算法不变|
|vendor/liveplan_types.py|LivePlan plan_refiner/types.py|仅行尾规范化|
|vendor/liveplan_formatters.py|LivePlan formatters.py|一处包内导入路径适配|
|decision_context.py|本地桥接|公开事件→作者类型；Markdown段落→作者检索；输出bash标签转换为JSON|

源码文本一致性测试已经直接对照下载仓库通过。作者源码和许可证随独立核心交付，不依赖研究资料目录或pma_baseline包。没有复制两篇论文的完整算法，也不据此声称原论文效果复现。

检索是词法BM25：改写、同义词、否定关系可能取不到正确记忆，必须保留原始读写工具作为补充。笔记可能错，返回中明确不是验证过的事实。每30行形成一个检索片段、返回最多5项；这是初始检索工程设置，不是论文已确定的最优参数。工作笔记与原任务目前不额外截断；长笔记仍可能增加成本，原容量机制保留。事件文件当前按顺序扫描，不宣称常数时间。

## 实现二：选择性有限暂停

新增 `task_control(operation, reason?, seconds?)`，仅候选开启时可见。普通任务仍并发；监察者已经看到具体问题且认为继续执行会扩大问题时，可请求pause。执行桥接复用GA现有可恢复取消与用户式输入。暂停在下一模型调用前生效，正在运行工具的取消仍取决于已有宿主能力，不保证副作用回滚或逐token停止。

暂停期间监察者用同一History继续调查。`intervene`发送具体纠正并释放暂停，然后并发观察后续理解、意图与动作；发现自身判断无依据可直接resume。wait自动释放，不能“停任务后等待任务产生新行为”。根handoff已经在等待，因此不会再叠加pause。

默认120秒、最大300秒的租约可由模型选择；到期自动恢复。正常故障与关闭释放；进程突然死亡最多留下有限租约。不会为了检验所有unknown无限锁住任务，也不保证期限必然够一次慢模型请求。任务暂停累计可能很高，必须测量而非宣称高效。

该控制不是LivePlan代码原样复用：其SWE-agent内部阻断与回滚不能直接执行GA。这里复用现有GA取消/续接、Python Condition等待等运行原语，新增小型桥接和失效租约。论文机制来源与实际代码来源分别记载，不把概念借鉴包装成上游实现复现。没有采用第二个维护/判断模型。

## 相对人工监察的具体对齐

再次查看人工Fyne原始011、014：前者先核Sscanf控制结果与测试同步，后者要求测试实际观察Refresh，而不是只检查已有指针/数量；两者都给出退出局部调查的依据。新视图让根要求、旧判断和之后行为一起可取，减少临时重新搜索；暂停提供“调查时不继续沿错误前提扩散”的选择。它们只提供这些行为所需的信息和权限，不保证模型自然学会正确策略。

人工Fyne的专业知识、已有题目熟悉程度和未完整计量成本仍是混杂。不得承诺此实现已达到人工水平。当前也没有复用人工答案或错误位置到提示词、测试任务输入中。

## 比较与验收

两个开关独立：decision_context / hybrid_control。共同母体都保留上一轮容量修复；初次集成试跑可以检验组合是否被模型正确使用，不能分摊每个组件的贡献。之后应在同一道Fyne/同模型/同预算关闭其中一项判别，再扩题源。不能为表现差的候选单独换题。

方法证据至少分四项：原要求遗漏与错误闭合是否减少；干预后的实际行为是否纠正；发现到送达/消费的时间与返工；额外token和暂停wall time。模型声明“理解了”、工具成功率和检索命中率都不是任务效果。

本轮：监察/中断回归287项通过；隔离/入口64项通过；另新增完整假模型工具循环1项通过（6次请求：重建、暂停、写认识、纠偏、读取反应、静默，无隐藏模型调用）。Fyne无网络容器真实导入及作者检索执行通过。真实runner预检通过，未调用任何模型API，未运行完整任务。

测试期间发现并修正：首次无笔记/无回执/无事件时resolve_read会抛FileNotFoundError；作者BM25实际路径在memory子包；一个新测试插入位置和运行cwd错误。不是服务失败或语义效果失败。作者仓库长路径checkout问题已用该新克隆的core.longpaths修复并恢复索引，未修改其源码内容。

下一实验配置见LITERATURE_TRANSFER_READY_20260913.md。未测语义有效性、误暂停率、成本净收益。保持“完整可运行候选”和“论文方法成立”的区别。
