# R2：监察者为什么把局部修复当成整体完成

## 范围与证据

本轮只审计，不修改实现或启动API。研究问题保持表示遗漏与不受支持的完成闭合。
原始run：clean-monitor-fyn-2.2.0-roadmap-tools-repair-20260913-r2；trial：fyn-2.2.0-roadmap__qNMpijs。
主要依据agent/monitor/monitor_private/audit/dialogue.jsonl的全部85条model_output、全部工具调用及关键原始返回、working.md写入、runtime_receipts、task_evidence/public_events.jsonl末段与original_task。这里的意图指模型公开表达及实际选用工具，不声称读取不可见内部推理。
人工对照重新读取20260907 Fyne原始interventions/archive/006、011、014、015；人工具有既往知识优势，不是公平模型能力比较。

## 核心判断

“编译+部分测试=>完成”是末端症状。更早发生了判定对象替换：
原任务要成立的具体行为 → 7个实现区域 → 每区本轮发现的修复清单 → 清单修好即整区COMPLETE → 编译成为唯一剩余问题。
因而末段并非从零拿编译证明全部行为，而是在错误的“功能早已验证完”前提上，拿编译解除最后阻碍。
这是基于行为链的解释，不是已完成因果消融。单次轨迹不能确定模型内部究竟因注意力、角色先验或上下文组织产生这个替换。

## 更元的差距：两个不同的提问

自动行为近似：“我指出的问题改了吗？还有哪个目标没打勾？构建是否终于通过？”
人工原始行为近似：“这个观察究竟能支持哪个任务判断？即使该观察成立，当前担心的错误是否仍可能存在？”
人工006非nil颜色不能排除忽略覆盖；011Get变化不能证明监听通知，Sscanf失败先检查测试前提；014指针/数量不变不能证明Refresh调用；015在准确起始版本做一次对照后释放，不继续穷尽未知。
所以人工不是更保守或永不放行，而是调查围绕有决策价值的行为差异。自动擅长具体局部修复，但把“没发现新的问题”当作覆盖已完成。

## Harness起了什么作用

- working.md以Target COMPLETE组织，主动context每次带回，形成把局部结论传播为全局前提的路径。工具没有强制这种schema，是模型自选；不能归因于字段设计强制。
- review_context默认近期行为/上次纠偏，原题无query为有界头部预览；有利于跟进，却可能强化当前局部议题。此次原题只初始化直接读一次，后续工具查询没有query；模型仍能主动重读，不能说原题不可获得。
- 新提示明确要求“区别要求与推断、问错误实现是否也能过、编译仅支持对应事实”，但行为仍未稳定做到。故缺一条提醒不是充分解释，再添同义口号没有可靠依据。
- 输入对称性：任务summary称全部完成、监察note称全部完成、最后纠偏聚焦编译；多个通道反复出现同一判断，不是多份独立证据。可能放大确认倾向，独立贡献仍待判别。
- 并发与延迟不是上述全部原因：绑定的降级发生在它已经读到缺口后；主题检查范围缩小与给Entry错误建议均可在本次实际观察时间内定位。

## 对机制研究的含义（不是实施方案）

不应只提高怀疑程度、固定多跑测试或追加更多字段，也不应因为模型能自由写文件就认为记忆维护目标已成立。
需要研究的是如何让“原任务行为、目前证据能支持到哪里、哪些判断仍未成立”持续约束自主调查，而不是只持续保存完成标签。
这与PMA维护记忆有联系，但复制存储/更新本身不能保证避免上述错误；可借鉴它明确的维护—消费连接，另行判别是否保住判断依据与未决事项。不能从本审计宣称PMA已解决此问题。
下一项候选应区分：证据已经到眼前却不使用；与证据/问题没有进入当前认知。前者优先从职责与判断任务组织判别，后者再看记忆输入；不一次堆叠，先给出可证伪比较。

## 边界

不能把人工轨迹认作同预算上界，不能保证自动模型只改组织就能达到人工结果；基础代码推理能力不足也未排除。
4/7较0/7是单次改善，不足以定位任何改动独立效果。审计不改方法或运行控制，也不以事后native信息作为新运行在线工具。
