# M1-C：最小被动视图与主动重建成本门禁（2026-08-25）

## 裁决背景

M1 FBR `r2-bounded` 在约 71 分钟后因监察者供应商 `DAILY_LIMIT_EXCEEDED` 终止。终止前 87 次监察决策消耗约 13,378,689 个监察者输入 token。主要工程原因不是单纯调用次数，而是旧实现同时：

1. 将当前边界、完整状态视图和大量工具结果被动注入；
2. 将此前大型边界 prompt 保留在模型对话历史中反复重发；
3. 又允许监察者通过工具读取同一批信息。

因此“主动工具”没有替代全量灌输，而成为重复信息通道。继续直接运行完整 M1 不满足成本贯穿约束。

## 阶段位置

在 M1 工程实现与下一次真实任务之间插入 `M1-C` 成本门禁。它提前实现原 M6 中与运行可行性直接相关的 active-view substrate，但：

- 不改变 M1 对创新 A 的验证目标；
- 不把成本改成第一篇论文的必要主贡献；
- 不允许以降本为由削弱持续 repair 监察；
- 不拥有真实任务晋级权，最终仍由完整真实任务裁决；
- M6 仍负责正式等预算消融、成本比较和最小组合冻结。

## 运行模型

### 外部可靠保存

Harness 持续保存：

- 不可变原始任务；
- 根 obligation ledger；
- 当前 repair episode；
- M1 语义对象、关系和版本；
- 完整公开轨迹、监察决定和文件状态。

外部保存防止信息消失，但不等于每轮全部注入。

### 最小被动唤醒视图

每次监察只被动接收：

- 当前公开事件的有界表示；
- 当前 repair episode 摘要；
- 根任务释放依据和 obligation ledger；
- 注意模式、风险信号和持久 notes；
- 轨迹、决策、测试、diff 与语义状态的导航索引；
- 当前 inspection loop 已返回的结果。

### 监察者主动重建

监察者根据当前判断自主调用只读工具：

- 重读原始任务；
- 查看最近增量或指定历史区间；
- 搜索历史轨迹与自己的旧决定；
- 查看完整 repair episode；
- 查看变更测试、测试契约、生产 diff 和工作区文件；
- 搜索语义 workspace，或按稳定 ID 读取完整对象和关系。

缺失于唤醒视图只表示“尚未加载”，不得推断为“未发生”。监察者只检索可能改变当前决定的信息，不以最大浏览量为目标。

### 持续身份

同一监察者的跨轮连续性由外部持久状态、公开归档、稳定对象 ID、repair episode 和主动重建保证。active 模式不再重发旧边界 prompt；这不会拆分为多个模型或多个监察者。

## 可消融实现

- `GA_M1_WORKSPACE_ENABLED=1`：启用 M1 持久任务—推理—证据 workspace。
- `GA_M1_ACTIVE_RECONSTRUCTION_ENABLED=1`：启用最小被动视图和主动重建。
- 不设置 active-reconstruction 开关时保留旧的对话历史/完整 active-view 路径，用于回退与消融。

每次监察调用记录 `monitor_context_view`：模式、消息数、实际 wire 字符数、可检索轨迹量、可检索决策量和当前 inspection 结果量。

## 非付费完成条件

- [x] 旧 prompt 不在下一轮重复发送；
- [x] 原任务、最近轨迹、repair episode、完整历史、测试、diff 和语义对象仍可主动获取；
- [x] 旧模式保持可关闭/回退；
- [x] RoadmapBench、TB2、Claw-SWE 和 Harbor adapter 可传递开关；
- [x] 静态编译与相关集成测试通过；
- [x] 实际 wire 大小已有运行时埋点。

## 真实运行门禁

下一次真实任务必须作为全新不可变 run，不续接 `r2-bounded` 的中间工作区。运行初期优先检查：

1. 每次调用的实际 wire 字符/token 是否不再随历史单调增长；
2. 监察者是否会主动查看测试、diff、repair episode 和原任务；
3. CORS、Request-ID、Session、MIME 类关键行为是否保持；
4. 是否因最小视图产生 representation omission、错误 SILENT 或错误 RELEASE；
5. 达到预注册成本预警线时停止，不允许再次耗尽整张日卡。

在完整真实任务前，离线测试只能证明工程连通性和信息可达性，不能接受 M1 或宣称能力保持。
