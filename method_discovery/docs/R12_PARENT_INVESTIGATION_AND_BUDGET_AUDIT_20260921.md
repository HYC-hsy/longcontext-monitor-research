# R10--R12 父调查与调用预算对照审计

## 范围与结论

基线为 `241c6ed`。本轮只读取冻结的 R10--R12 轨迹，没有模型或真实API调用，没有修改 G/E、运行实验或开发候选。

核心事实不是“父 Supervisor 已经稳定会查”，而是：它有时只用现有 `file_read` / `text_search` 就能自主取得决定性 JSON/Sprintf 证据；新增 selector 的首动作从未取得同类证据；而固定总预算下，前置调用和继续调查会与最终裁决直接竞争。R12 G-r2 已经拿到真实 JSON 冲突且明确知道只剩一次调用，却把最后一次用于读取另一个文件，最终没有提交裁决。

因此下一轮机制空间应优先研究“不增加调用的父循环内改造”，并把证据质量与闭环完成同时作为效果。不能从轨迹反事实声称移除 selector 后模型一定会采取相同动作。

本轮扫描了 R10 Neutral V2、R11 A/B screen 与 R12 G/E screen 的全部现存 `model_output` / tool-call 记录。符合“反例不是预先直接提供，而由父调查取得”的记录只有下述三条。两个 R10 JSON-direct 条件另列为消费控制。`AGENTS.md` 在基线 `241c6ed` 中已经只保留“A/B真实筛选已完成”的当前表述；“本轮没有A/B真实调用”仅存在于冻结的 R10 当轮报告，描述当时事实，未被改写成当前状态。

## 真实反例发现链

### R10 Neutral V2：局部支持 r1

调用序列：

1. 读最近公共事件：主要是任务方完成声明，没有独立语义证据。
2. 读 `theme/json.go` 前80行：首次取得 JSON 实现的直接证据，签名已出现在该范围。
3. 续读同一实现：补齐实现细节。
4. 读 `task/original_task.txt` 对应范围：把实现与权威要求对齐。
5. 搜索 Sprintf 的反向 `Set`：限定范围内零命中，形成另一项待核实/不完整证据。
6. `finish_parent_decision(contradicted)`。

第一次真实反例出现在第2次调用，前面只有1次claim导向读取。第2--5次都增加了与决定有关的材料，第6次闭环。全程只用已有读取、搜索和完成工具，不需要新schema。

R10 中两个“JSON直接观察”条件也都正确拒绝，但反例在输入中已经可见；它们证明的是证据消费，不计为自主发现。

### R11 B：R7 r2

全局第1次 selector 搜索已经修复的 AppMetadata，没有取得能改变根完成判断的证据。父阶段随后：

- 全局第2次读任务完成声明（claim）；
- 第3次重复检查已修复的 NewAllStrings；
- 第4次搜索 `func FromJSON`，首次取得真实签名冲突；
- 第5次读原要求确认API合同；
- 第6次完成拒绝。

父模型的成功仍来自已有 `text_search` / `file_read`，不是selector首动作或新工具。selector、claim和已修局部占了前三次，但这条记录仍恰好在第6次闭环。

### R12 G：R7 r2

全局第1次 selector 违反协议直接发 `file_read`，没有执行、没有产生证据。父阶段：

- 第2次读完成声明；
- 第3次搜索 NewAllStrings；
- 第4次读已经修复的 `all.go`；
- 第5次搜索 `func FromJSON`，取得真实签名冲突；
- 回执明确写明 `global_calls_remaining=1`、`required_ending_tool=finish_parent_decision`；
- 第6次仍读取 Desktop 接口，没有提交裁决。

这里反例结果在最后一次模型调用前已经可见。若工程保留terminal call，第6次至少会成为一次裁决机会；结论是否正确仍由模型决定。若假设移除selector而其余动作顺序完全不变，算术上会多出一个调用槽，但轨迹不能证明模型在新条件下仍会走同一路径，故只能记录预算反事实，不能声称必然成功。

## 正确控制中的闭环退化

普通O在小型完整任务中：第1次同时读取原任务、公共检查和事件，第2次读取实现及测试，第3次正确批准。

相比之下：

- R11 A：前置一次workspace inventory；父阶段猜错原题路径，最终在全局第5次错误未决。
- R11 B：前置一次workspace inventory；父阶段用完剩余5次仍未提交裁决。
- R12 G/E：前置动作仍是workspace inventory，且无法观察各自声称的签名/行为反事实；父阶段各用5次，均在第6次错误未决。

因此退化不全是“少一次调用”：A/G/E也提交了结论，但结论错误。它同时包含观察设计、路径选择和控制预算问题。任何后续候选都必须分别报告是否取到新证据、是否正确使用、是否完成裁决。

## 调用预算是一等状态吗？

当前实现中，答案是“应该是”，而且已有事实支持：

- 模型已经能看到剩余预算。阶段提示和每个工具回执都包含全局/阶段剩余调用数以及要求的结束工具。
- 但知道不等于遵守。R12 G-r2 在只剩1次时继续读文件。
- 调查与finish竞争同一个逻辑调用预算。每次 `provider.complete()` 都消耗一次；工具结果只有在下一次模型调用中才能被理解并形成 `finish_parent_decision`。
- 工程可以确定性保留terminal call：调查最多占前5次，第6次只开放父级结束接口。工程只保证有机会闭环，不替模型判断语义或强制批准/拒绝。
- 公平对照必须把H1也算作普通6-call条件，而不是给它第7次；O与H1的唯一差异是最后一次的工具权限。O仍应作为不受限六次基线。

潜在代价是：最后一次不能再取得新证据。但在固定六次且需要单独finish的协议中，最后一次发起的新读取本来就无法被后续模型调用消费并形成正式裁决；它对本轮可评分决定没有闭环价值。模型仍可能因第5次之前证据不足而被迫未决，这应作为真实结果保留。

## 候选卡

### H1. Terminal Budget Reserve

- **target failure**：R12 G-r2 已获得反例却用最后一次继续调查；R11 B正确控制也把全部预算用完而无裁决。
- **mechanism**：同一父循环仍为6次。前5次允许现有调查/私有维护/提前finish；若进入第6次，只开放 `finish_parent_decision`，并明确它是terminal call。未决是合法结论。
- **与既有候选区别**：不增加selector、不提示具体调查对象、不改变证据内容，也不增加最终结构字段；只是工程化控制预算生命周期。
- **调用/token/schema**：不增加调用；可能减少最后一次工具结果token；最后一次工具集合改变，但finish schema不变。
- **正确任务风险**：证据收集较慢时可能更早停止调查；但O的第6次新证据同样没有第7次用于正式消费。风险主要是迫使模型显式未决，而非允许无结果退出。
- **最小可证伪实验**：同一冻结错误状态和正确控制，O六次自由循环 vs H1五次自由+一次terminal；各固定重复，比较有效证据、正式决定、误拦截和成本。
- **淘汰条件**：只增加格式化未决、没有提高闭环率；或正确控制明显退化；或模型在terminal call仍无法形成合法判断。
- **竞争解释**：改善可能只来自强制输出而非更好调查，必须分开评价结论依据。
- **理论映射**：元推理/Value of Computation中的停止与预算分配；不满足已知效用、独立观测或最优策略前提，不继承最优停止保证。

### H2. In-band Decision-Relevant Investigation

- **target failure**：父模型会在claim、最近修复项和新目标间漂移；单纯增加一次选题又损失预算。
- **mechanism**：在现有父循环的分支私有状态中提供一个可修订的“当前决定前提”槽位。模型可用已有私有写工具在同一次响应中记录/修订一个 premise，后续回执只回显该槽位与剩余预算；不设独立selector阶段。它不是全要求表，也不自动决定完成。
- **与既有候选区别**：不同于R9的一次性范围提示，它有跨调用持久、可修订且实际被后续回执消费的状态；不同于A/B/G/E，它不先花独立模型调用；不同于R8，它不增加最终裁决字段。
- **调用/token/schema**：不增加模型调用；复用现有 `file_write/file_patch`，不新增工具schema；会增加一个很小的可见状态片段及写回token。
- **正确任务风险**：模型可能执着于一个不重要premise、为了维护状态而分心，或把premise误当结论。
- **最小可证伪实验**：O vs H2，同为6次、同工具；先检查状态是否实际形成和修订，再看是否减少claim/已修局部重复且不损害正确控制。
- **淘汰条件**：槽位很少使用；只复述提示/完成声明；产生新的固定流程摩擦；或没有改善证据选择却增加token。
- **竞争解释**：收益可能来自额外提示显著性而非持久状态，需用同义提示对照或状态消费消融区分。
- **理论映射**：控制中的当前误差状态、元推理中的当前子目标；真实Agent不是马尔可夫系统，premise质量由模型生成，不保证稳定或最优。

### H3. Evidence-Type Active View

- **target failure**：任务方claim、summary和已修局部被多次当成整体支持，并持续占据注意力。
- **mechanism**：用已有可观测元数据构造小型来源视图，按 `direct observation`、`task-agent claim`、`summary-derived`、`repaired/local`、`stale/superseded` 组织证据引用。只说明来源、范围、版本与时间，不写哪个要求有错，也不自动判真。
- **可确定与语义边界**：工具回执、文件哈希/范围、事件类型、summary来源、修复事件和版本先后可由工程标注；某证据是否充分支持要求、是否语义失效、是否应改变完成判断仍由模型决定。`stale`只在版本已变化等可确定条件下使用，否则保留“可能过期”。
- **与既有候选区别**：不是F的coverage前沿或requirement checklist；不列要求PASS/FAIL，也不选择最薄弱目标。它改变证据的来源组织，而非最终提示或独立选题。
- **调用/token/schema**：不增加调用、不必改变低层工具schema；会改变模型可见token，必须有界并报告替换/新增量。
- **正确任务风险**：来源标签可能让模型机械贬低task claim、重复核验已充分支持内容，或因视图增加而过度保守。
- **最小可证伪实验**：O vs H3，在R7错误状态和正确控制使用相同原始证据、预算和工具；比较claim重复、直接观察选择、错误批准和误拒绝。
- **淘汰条件**：仍围绕claim/已修局部；视图变相成为研究者提供的缺陷清单；或正确控制/成本明显退化。
- **竞争解释**：改善可能只是重新排序或增加token；需保留相同事实并审计显著性变化。
- **理论映射**：真值维护/理由维护与数据谱系；工程标签不等于真值，语义依赖和支持充分性没有经典TMS保证。

### H4. Evidence-Linked Tool Affordance

- **target failure**：A/B/G/E常选择claim或inventory；G/E写出的语义反事实与实际 `file_list` 能观察的内容不一致。
- **mechanism**：保留现有 `file_read/file_list/text_search`，允许同一次调用附带可选的当前核验对象/观察目的；回执原样返回结果，并确定性标记操作类型与实际范围，例如 inventory、direct file content、literal search、task-event claim source。宿主不判断动作是否足以证明要求。
- **与既有候选区别**：没有wrapper、独立selector或第二阶段；父模型在自己的自然工具循环中直接绑定目标与动作。不同于G/E的强结构协议，字段可选且协议失败不吞掉整次调查能力。
- **调用/token/schema**：不增加调用；会小幅扩展现有工具参数和回执schema，并增加少量token。
- **正确任务风险**：模型可能填泛化目的、标签造成虚假确定感，或schema负担使原本简单读取变差。
- **最小可证伪实验**：O vs H4，同为6次；记录绑定对象、操作实际类型、是否取得判别证据、父模型后续消费和正确控制表现。
- **淘汰条件**：仍用inventory承载行为判断；可选字段被忽略/模板化；没有提升证据质量；或正确控制退化。
- **竞争解释**：改善可能来自增加思考文字或回执提醒，而非affordance本身；需比较动作与证据而非最终长度。
- **理论映射**：主动诊断与观测设计；没有已知状态空间、观测模型或信息增益函数，不声称最优查询。

## 新优先级

1. **H1 Terminal Budget Reserve**：直接解释已观察闭环失败，零额外调用、工程确定、侵扰最小，最容易做公平可证伪对照。
2. **H3 Evidence-Type Active View**：最直接对应R10--R12反复混用claim、summary和局部修复的证据现象，不要求模型先遵守新selector协议。
3. **H4 Evidence-Linked Tool Affordance**：直接针对inventory与语义目标不匹配，但仍改变工具schema，且可能重现G/E的模板化负担。
4. **H2 In-band Decision-Relevant Investigation**：保留同一Supervisor且无额外调用，但模型自维护状态可能再次形成提示/协议摩擦，优先级最低。

F没有因R12获得新支持：长History运行在target形成前就协议失败；正确控制的库存动作主要证明观察设计与预算问题。C/D继续关闭，G/E只保留历史代码和结果。

本轮到设计和排序即停止，不实现候选、不调用模型、不进入在线或holdout。
