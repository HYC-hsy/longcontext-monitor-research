# 请求时效感知候选：实现与工程验收

## 问题、边界与实现

承接 MEMORY_ASYNC_RESEARCH_AND_OPTIMIZATION_20260913.md 的调查。上一轮短 wait 不等于及时反应：监察者一次调查包含多个模型调用，期间任务仍推进。本候选只补充模型判断资料是否可能过时所需的态势信息，不声称解决了语义记忆或整个控制器。

- `monitor_agent_core/live_awareness.py`：每次普通请求准备时，对 synopsis、原始公开事件、干预回执做 stat；报告相对上次采样是否变化和间隔。没有读取正文、语义分类、正确性判别或新增模型。
- `agent.py`：`monitor_live_awareness` 默认关闭；开启后与现有自然 working.md 请求视图组合。临时视图不追加到持久 History；压缩维护请求不采样。不改变自主工具循环、初始化、wait、并发或强制纠偏。
- `workspace.py`：现有 file_read 增加可选 `tail=true`，返回末尾 count 行及原行号；仍可读任意旧范围或使用 code_run。保留完整文件 hash，因此当前扫描成本仍为 O(文件大小)，不是后台实时流。
- GA adapter → Harbor 环境透传 → manifest 环境清除列表均补开关，防止宿主开关丢失或污染其他条件。PMA 同步基线路径未改。

这不是新的第三层语义表示，也不要求每次都检查最新日志。文件变化不等于偏移；文件不变不等于已理解。采样发生在请求准备时，不保证模型返回时资料仍新鲜，不能宣称消除 API 延迟或天然超过 PMA。

## 验证与限制

首轮 33 项通过；扩大到 255 项时发现三处旧断言：W 的两个断言仍假设完整 review 不压缩；一个协议测试依赖旧错误文案。修正为完整交换尾部、协议配对、容量约束及实际异常类型后 255 项通过。未恢复旧容量缺陷、未放宽工具协议校验。另补真实 worker 函数的假模型容量故障测试，确认故障不会从下一 wake 继续膨胀。

最终结果与运行准备见 LIVE_AWARENESS_READY_20260913.md。全部工程测试使用假模型；不是语义效果证据。工具自由度、双层观察、同会话和任务并发保留。未引入任务源码或隐藏 verifier 到在线信息中。
