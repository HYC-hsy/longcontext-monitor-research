# 持续监察的一致性优化：统一设计与实施门禁

日期：2026-09-08。用户确认开始系统性优化；本次交付统一设计，不修改执行代码、不启动真实任务。
研究仍处于五阶段路线的阶段 1 原因判别及其候选准备，不意味着原因全部确定，也不恢复旧 M1–M7 执行顺序。

## 1. 一个目标，而不是新增组件清单

保持原任务要求、当前证据与下一步行动之间的一致性。既避免遗漏和不足证据下的错误闭合，也避免监察者用自己的推断制造额外要求、长期阻止完成。后者是控制可靠性约束，不替换原论文主问题。

对应候选贡献：A 承载当前可修订理解；B 修订包括监察者自己提出的判断；C 完成判断不把局部支持外推，也不把所有未知升级为阻断；D 按判别价值选择观察和恢复。当前不承诺四项全部成为最终创新，不把工程整理包装成算法贡献。

主体保持独立 Clean Monitor、单一持续身份、同一会话、并发任务、主动工具、模型自主等待及可恢复强制干预。任务观察仍只有 synopsis 导航与原始公开证据两层。私有记忆不构成第三层任务证据。

## 2. 设计前核验出的重要事实

当前 `agent.py:MONITOR_SYSTEM_PROMPT` 已要求测试不是 ground truth、区分假设与观察、修正旧建议、保留根任务、局部释放和避免完美主义。失败不能简单解释为这些句子没写；不再通过重复类似句子当作新机制。

人工原始 011 要求直接比较标准库行为，014 检查刷新调用传播并限制额外基础设施，015 用干净起始版本复现旧失败后停止。这是三种按疑问选择证据的实例，不是应硬编码的三类任务。

自动审议 19 能识别接受后未落实、28 能追踪 Bytes 的具体缺口、39 确认主题修复、43 恢复根范围；必须保留这些能力。审议 78/79 却把反向解析测试预期当作契约，task 452/453 转向自定义解析。这证明既有原则没有稳定落实，不证明某一种新表示必然解决。

工程当前在每次 provider.complete 加入输入后判断容量，超过阈值即先做一次全历史维护，再尝试裁剪。保护首轮和至少 16 条近期消息可能使裁剪无法到目标；新笔记插在首轮后，较旧保留消息仍位于它之后。维护使用相同 system 的行动职责，而临时 user 指令要求只写笔记；首份笔记实际混入伪工具调用文字。

另有独立交互风险：runtime 在 completion 上将 wait 转成通用 continue，completion 超时也返回 continue。它不等于模型提出了有根据的新修复；可能促进重复完成/无方向续跑。必须单独核验，不能借本轮直接改成超时自动批准。

## 3. 各部分只承担一种职责

|部分|负责|不负责|
|稳定 system|身份、信息边界、通用协作原则、工具地图|具体题目答案、阶段代号、强制推理表格|
|近期 History|保持当前调查、已发建议、后续回应和工具观察的连续性|永久堆积所有原始材料|
|自然 working note|保存当前会影响未来决策的理解，允许修订和撤回|逐轮流水账、固定 obligation ID、把推断变成新指令|
|原始公开归档|可靠保存任务、动作、结果和历史材料，供自主回查|替模型判断语义正确性|
|运行时|并发、游标、工具协议、送达与容量事务、可审计归档|判错分类器、隐藏 checker、替模型决定修复范围|

不引入第二维护模型，不增加领域专用工具，不恢复旧 ledger/repair ID 或语义匹配接口。

## 4. 认知维护路径：一个可控的交接，而非反复重新读懂任务

### 普通过程

初始化读取原任务并形成理解，随后照现有主动循环观察。普通唤醒继续当前 History，不自动灌入全部任务/笔记/归档，也不额外调用维护模型。模型觉得有未来价值时用已有写工具更新笔记，不规定每轮必写。

### 容量交接的实现方向

1. 在调用维护模型之前，先构造本次待退休历史区段及合法裁剪计划。区段是完整工具协议边界，不把一次 wait 当作语义修复已结束。
2. 将“本次只是交接笔记、不可执行动作”的职责设在维护请求的明确模式中；保留原身份和证据边界，暂不应用普通 review 必须控制动作的指令。仍是同一模型读取同一已有历史，不启动独立监察者、不在每轮运行两个模型。
3. 交接保存当前理解，而非让模型重抄整道题。对未来重要但不确定的判断保留其不确定性、理由和来源；模型自定组织形式。新笔记不能成为任务 Agent 的新要求。
4. 交接成功后一次性提交笔记与合法历史裁剪；旧版本、被退休记录及来源均可检索。失败不删除历史，不伪装正常静默。
5. 当前交接说明按其生成时间放置，避免新结论插在旧调查之前而缺乏时序含义；旧续接文本可以归档，不作为多份当前权威反复携带。具体位置须验证工具调用/结果配对不受破坏。
6. 明确处理未达到容量目标的原因。没有新的可退休材料时不再次付费生成同一交接；过大工具结果可保留完整外部原文及可回查位置，不能静默截去中段还宣称全文已保留在模型视野。不得靠无限跳过压缩逼出 provider 上限错误。

首轮历史不等于稳定知识，不应仅因它是首轮就永久保留其中目录遍历等大段结果；但原始要求及初始化的重要判断必须可续接、可回查。近期修复也不能仅凭固定 16 条消息就声称完整保护。

容量阈值、目标余量和受保护近期范围是待实现时验证的工程参数，不宣称已找到最优值。此次不自动缩小模型可用上下文，不将节省 token 建立在强制减少必要调查上。

## 5. 决策路径：保持判断可被反证，而不是强制每轮深审

监察者看到异常后仍自主决定是否调查或直接提醒。与现有行为的目标区别是：它要能保留并修订导致干预的依据，而不仅追踪干预是否执行。

- 明确冲突：可以直接指出，不强制先列多个解释。
- 解释不同将导致不同修改：优先选择能区分解释的观察，或让任务 Agent 做这种观察；不将一个含糊失败直接转成生产修改命令。
- 修复明显扩大：回到原任务及已存在的能力边界判断必要性；不规定一律最小代码、不禁止合理的大修改。
- 干预后：持续看公开理解、行动与结果。能接受合理探索；新证据推翻自身判断时撤回或缩小要求。
- 局部退出：介入理由已解除或已有依据允许自主继续，即可静默；保留尚未解决的其他根要求。
- 根完成：依据完整任务范围和适用证据作判断，不能因为局部仍可进一步优化就否决，也不能因全部局部标签关闭就自动批准。

这不是五个新工具或五个必填字段。最小候选可以让模型自用的笔记和自然干预表达“我为何认为需要这一步，以及什么会改变这一判断”；具体文字与写入频率由模型决定。

实现差异必须超越重述现有 system 原则：重点比较判断依据是否在续接中存活、被新证据实际修订，以及是否改变干预行为。如果仅有措辞变化却没有不同可观察过程，应如实判为弱候选，不包装成新架构。

## 6. 分阶段实施和停点

### S0 本轮：统一设计

完成代码核验、人工锚点复核、职责边界、改动清单和验收设计。只落文档。交付后停止。

### S1 下一实施阶段：稳定连续认知底座

按目的分步，每步代码新增删除合计不超过 600 行：

1. `monitor_agent_core/agent.py`、`provider.py`：分离维护与行动的请求职责；保留身份、模型、工具协议与错误可见性。测试检查维护不发干预、结束后正常角色恢复、失败无历史丢失。
2. `provider.py` 及必要的私有归档辅助：先计划可回收区段，再交接提交；避免无有效进展的重复整理、重复当前笔记和错误时序。验证大工具结果、长 review、连续多次容量触发、可回查原文、消息配对和真实 usage 记账。它们只验证工程，不评判笔记语义质量。
3. 现有 integration/runner 路径：审查超时归档，确保失败也保留公开输出和状态；不把失败伪装成功。独立提交/记录，避免与方法效果混淆。
4. 联合回归：监察阻塞时任务推进、干预实际交接、实际 uptake 不等于回执、同会话恢复、根 completion 身份绑定保持。完成汇报，真实启动前停。

若要改变 completion wait/timeout 的动作语义，先另列设计与用户确认；本阶段不默默改变它。不动主要模型、预算或任务选择。

### S2 后续候选：可修订依据驱动的持续纠偏

在 S1 底座上只增加一个相干候选，不能再把记忆、调度、成本、完成策略同时改掉后笼统归因。先明确可观察差异，再实现自然状态维护/消费的必要连接；模型仍有自由调查与工具执行。

同题比较优先 Fyne method_dev：保留同任务版本、任务/监察模型、turn/time 预算与公开信息边界。S1 工程底座和 S1+候选的差异必须可追溯；历史人工与当前旧 run 仅作诊断参考，不能替代匹配对照。是否运行两分支、成本额度和启动均需用户批准。

共同判别：是否减少错误测试推动的实现改写、无依据范围扩展；同时保留 Bytes/variant 修订、实际 uptake 和根覆盖。不要求复现人工每一句话，也不固定这些领域例子为规则。形成可比结果后再轮换其他 method_dev 题，holdout 不参与选择。

## 7. 判失败与回退，不只判收益

- 维护减少但必要依据丢失：能力退化，不以省钱接受。
- 监察变得什么都怀疑、只问问题不干预：不成立。
- 为每次简单问题都执行反例实验：调查负担增加，不成立。
- 局部容易退出却遗漏根要求：不成立。
- 最终通过只因为调用更多：报告计算增益，不宣称机制有效。
- native 通过但继续循环：分别报告产物和控制结果，不能只报 1.0。

记录介入依据、实际读到的材料、送达/采纳、对旧判断的修订、局部退出、根覆盖及 input/output/cache/调用/延迟。模型自述仅供解释，不独立证明正确。人工监控成本未完整计量，不作等预算优胜声明。
