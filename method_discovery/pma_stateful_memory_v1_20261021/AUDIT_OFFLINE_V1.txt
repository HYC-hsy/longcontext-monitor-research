Implemented and directly tested
-------------------------------
* Strict JSON/source and state contracts, exact source spans, role/purpose and
  current-window checks; no cache-based visibility bypass. This validates
  structural consistency, not semantic truth.
* One method-local SQLite transaction for snapshot, archive delta, commit
  record and event frontier; same-ID/same-hash idempotency and CAS. The DB is
  not the benchmark SQLite task.
* Host EventSeq with atomic action/result batch identities, GoalLedger epoch,
  contiguous pending prefix; no selection while a frozen tip remains pending.
* Pinned PMA BM25 ranking, mandatory goal/open-gap/focus/direct state/history
  bundles and whole optional-bundle omission. Index is derived and rebuilt
  after commit, not a second writable memory bank.
* Original-base-only proposal application; audit codec round-trip and
  before/candidate hashes; one shared precommit repair credit, at most five
  successful-cycle logical calls, selection with no repair/retry.
* Strict silent/remind and host-derived anchors. FakeTask delivery is a
  separate auxiliary user turn, checked after actual accepted fake response;
  attempted/unknown delivery is not blindly resent.

Important limitations — NOT certified complete
----------------------------------------------
1. This is a method-local FakeTask chain, not an actual
   single_run → GA/Harbor/native-SHARED or Docker product lifecycle. No
   source-bound deployment certification exists for this candidate. There is
   no live endpoint/credential path in the package and no future-live command.
2. Frozen workset projection now excludes unselected current objects from the
   audit view, while the full candidate is preserved for CAS commit. This has
   a direct hidden-object test, but the complete archive/linked-gap and scope
   visibility matrix has not been exhaustively verified. Large mandatory
   worksets can still fail the fixed input budget; they are not silently cut.
3. The fixed checklist is not wholly discharged by 43 focused tests. In
   particular, full Requirement/gap migration matrices, output truncation and
   provider outcome-unknown typing, all archive witness variants, GA13 fixture
   migration and host request-boundary provenance remain unverified.
4. The offline provider callback has no built-in retry or network fallback,
   which is safe for this stage, but it is not a production RoleTransport.
   Native context guard is defined yet cannot be verified against a real
   profile/window without a future separately authorized integration.
5. Fake audit answers are scripted. An incorrect but valid clean can still
   commit a semantically wrong candidate; a source-valid reminder can still
   overgeneralize. Neither coding tests nor codec size prove model accuracy,
   Task benefit, or average live cost.

Consequently this stage is a safe partial implementation, not an accepted v1
or a basis for seeking immediate real-model execution. The remaining work
requires explicit engineering scope review; the current OFFLINE_CONFIG is
execution_authorized=false. No SQLite historical task script, real model,
real Task, official evaluator, training or scoring call was made.
