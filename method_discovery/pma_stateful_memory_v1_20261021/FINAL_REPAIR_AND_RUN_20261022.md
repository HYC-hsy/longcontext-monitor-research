## 二、必须补完：移除人为代理 token 硬拒绝
这部分尚未包含在上述补丁，不要误称已解决。
32,768 是本项目固定的 o200k_base 代理输入阈值，不是模型官方窗口，也不是基准时限。当前诊断路径不应因为超过它或本地计数器不可用而终止任务。

限定修改位置与行为：

1. budget.py / TokenProxy
- 默认 input_limit=None；enforce 保留接口和可用时的离线统计，只有显式整数限制才执行旧硬拒绝。
- 显式限制模式可保留用于旧合同反例测试，但当前真实诊断路径不得隐式落回它。
- 默认软模式下，tiktoken 导入、编码缓存或计数失败不能成为启动门禁。计数不可得时记录 proxy_tokens=null、明确原因和真实字符/字节数；不得伪造 0，也不得换成另一个字符数硬门槛。
- 不为计数主动发外部 HTTP 或补下载。已有本地编码可直接统计；缓存缺失则直接记录未知，不能让 get_encoding 隐式下载阻塞。只局部处置计数依赖，不全局 monkeypatch 网络以免误伤真实 Task。显式严格模式可以因必需计数不可用而失败。
- 只捕获计数依赖/统计自身失败，不吞掉非法消息、来源错误、存储错误、取消或真正传输故障。

2. retrieval.py / WorksetBuilder.build
只改 TokenProxy 不够，这里还有独立的 mandatory、earliest_atomic_event、omission_manifest 三处超限拒绝。
- 区分“工作集软目标”和“请求硬门槛”。可保留 32,768 为选择可选材料的软目标，但它不能否决必需材料和整个任务。
- 必需任务依据、强制工作集、最早一个完整原子观察批次即使超过软目标也要保留；不能跳过最早观察或拆掉动作/回执。
- 后续观察按原有连续前缀规则分批，未纳入的保留 pending；不要为了无上限把全部 backlog 和全部历史一次塞入。
- 可选检索材料仍依原排序和整组规则择取；超过软目标可不加，但不能删必审对象。
- omission 清单本身超目标不得导致任务失败。
- 统计未知时保留必需材料及最早完整批次，暂缓额外 backlog/可选检索，明确说明无法估算；不能将未知当作已超限。
- 保留显式严格模式及其测试，避免改坏已有测试用途。

3. engine.py 和 audit.py 中的通知、发送和预检查
- 核对 _call、维护工作集、审核预检查、候选修复、选择工作集和选择发送全部使用新默认软策略。
- engine.py 原约 338、631 行及 audit.py 原约 125 行仍向模型宣告 32768 为硬 limit，须改成真实的 soft target / nullable explicit limit，不能代码放开而提示词仍谎报。
- 审核请求超过软目标，不得因此消耗唯一修复机会要求模型“缩小候选”。该旧分支仅供显式严格/注入错误测试保留。
- 超过代理目标不是审核问题，也不是模型故障。
- 不扩大为吞异常继续跑；真实拒答、结构错误、来源错误、失败审核、未知请求结果仍按原合同处理。

4. 不扩展到其他方法、框架或真实窗口
- 无需重写 experiment_runner、GA 或 Harbor。
- 保持当前 diagnostic 的 native_context_policy=off、research_capture_policy=best_effort，不恢复外部 token 计数门禁。
- 不声称代理估算等于真实模型 token。模型实际窗口与请求合法性仍存在；若服务端明确报真实上下文超限，单独归类，不伪装成 32768 研究预算。
