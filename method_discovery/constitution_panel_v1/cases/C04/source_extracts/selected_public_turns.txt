#### Root Causes Fixed

##### 1. CA Certificate Malformation (CRITICAL)
**Problem**: CA certificates generated with `ExtKeyUsage: x509.ExtKeyUsageServerAuth` fail x509.Verify() chain validation with error:
```
x509: certificate specifies an incompatible key usage
```

**Root Cause**: RFC 5280 § 4.2.1.12 states that CA certificates used for chain validation must NOT have ExtKeyUsage restrictions. The presence of `ExtKeyUsageServerAuth` in a CA cert violates this constraint.

**Fix** (`listen_test.go` lines 287-293):
```go
// When isCA=true:
KeyUsage: x509.KeyUsageCertSign | x509.KeyUsageCRLSign
// NO ExtKeyUsage restriction for CA certificates

// When isCA=false (end-entity server cert):
KeyUsage: x509.KeyUsageKeyEncipherment | x509.KeyUsageDigitalSignature
ExtKeyUsage: []x509.ExtKeyUsage{x509.ExtKeyUsageServerAuth}
```

##### 2. Test Oracle Bug (3 mTLS tests)
**Problem**: Tests used `tls.Dial()` and checked `if err == nil` to verify handshake rejection, but Dial only establishes TCP connection, not TLS handshake.

**Fix**: Replaced with HTTP GET request + bounded read to force actual TLS handshake:
```go
resp, err := client.Get(addr)
if err == nil {
    io.CopyN(io.Discard, resp.Body, 1024)
    resp.Body.Close()
}
```

##### 3. Client Certificate Key Usage
**Problem**: Client certificates included `KeyUsageKeyEncipherment` which is incompatible with TLS 1.3 and modern cipher suites.

**Fix** (`listen_test.go` line 339):
```go
// Client certificate (isCA=false, ClientAuth):
KeyUsage: x509.KeyUsageDigitalSignature  // Only DigitalSignature
ExtKeyUsage: []x509.ExtKeyUsage{x509.ExtKeyUsageClientAuth}
```

##### 4. Clock Skew Protection
**Fix**: Added 5-minute NotBefore buffer to prevent clock skew issues:
```go
NotBefore: time.Now().Add(-5 * time.Minute)
```
