# GA-style PMA conversation-history variant

Method base: `f838e742d6b6d10d32d05eba3d2c989561b7cbcb`. This is a separate experimental variant, not a replacement for the base. Task-start P1/P2 and every-eight-eligible-step wake cadence, predictive memory and reminder prompts, actor and bank policies remain as in the base.

- Each task has two separate conversations, one for P1 and one for P2. Each phase retains its own earlier user prompts and public assistant outputs. P1 retains actual memory tool call IDs, arguments and operation receipts; P2 learns about P1's new writes through the updated bank, not a merged conversation.
- Each wake's current prompt still contains the original task, the newly accumulated eight-step trajectory window and the current bank. Earlier windows are carried in history, not added again as the current trajectory. Previous bank snapshots remain in the history and can be stale.
- The host-side `ga_context_history.py` contains verbatim copies of GA's `compress_history_tags`, `_sanitize_leading_user_msg`, `trim_messages_history`, and `_msgs_claude2oai`; tests compare their AST against the pinned GA source. The copy avoids importing GA's container-only dependencies into the host worker. GA actor code itself is not changed.
- The copied GA default `context_win=30000` uses its serialized-character cap of 90000, target 60%, and compression cadence 5. This is the GA default for non-DeepSeek models, not proof that a particular private GA profile uses those values. Before comparison verify the actor's actual settings and explicitly report differences. As in GA, the rule does not guarantee that one oversized current prompt will fit.
- GA-style history uses typed content blocks. P1 tool-use/receipt pairs are converted to LiteLLM messages, and episode/transport wrappers forward `message_history`. Provider-issued signed thinking blocks, when present, are retained unchanged as opaque provider-only metadata for the same API continuation and redacted from the memory payload audit. GA content compression does not alter signed blocks, so this protective detail is not byte-identical to compressing GA's own thinking blocks. No hidden reasoning text is used as user-facing content or saved in trajectory summaries.
- A malformed/ID-less native tool batch, ambiguous native/text fallback, or a reasoning+tool response lacking required provider blocks fails explicitly before bank writes rather than fabricating history or partially applying a batch. Existing text-only XML fallback retains actual operation receipts as labeled text.
- This branch still descends from f838's older runtime; do not assume its launcher implements uncapped policy. Integrate the method with the verified common dataset runner and explicitly validate all effective limits separately before any trial.
- Offline tests use stubs and AST-isolated parts of the code. They do not establish that an installed LiteLLM/Anthropic version will accept real signed history. An offline test of the actual installed adapter's outbound payload and redacted audit is required before any paid run. No model calls are authorized by this document.
